Chapter 09 — Templates

Generic programming in C++: write type-independent code once, let the compiler generate it for every type you need.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

9.1 What Are Templates? Generic Programming

Imagine writing a max() function for int, then another for double, then another for std::string. The logic is identical — only the type changes. Templates solve this with generic programming: you write the algorithm once using a placeholder type, and the compiler generates a concrete version for every type you actually use.

Templates are a compile-time mechanism. There is no runtime overhead — the compiler stamps out specialised code during compilation, giving you the same performance as a hand-written type-specific function.

9.2 Function Templates

A function template is declared with a template parameter list before the function signature. Both typename and class are interchangeable as the keyword for a type parameter: 

// Both forms are identical — "typename" is generally preferred
template<typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}

// Usage — compiler deduces T = int
int    biggerInt    = maximum(3, 7);        // T deduced as int
double biggerDouble = maximum(2.5, 1.8);   // T deduced as double
char   biggerChar   = maximum('z', 'a');   // T deduced as char
typename vs class Inside a template parameter list, typename T and class T are completely equivalent. The convention is to use typename for generic types (clearer intent) and class only when you explicitly mean a class type.

9.3 Template Type Deduction vs Explicit Specialisation

The compiler can usually deduce the template argument from the function arguments. When it cannot (or when you want to override the deduced type), you provide it explicitly: 

template<typename T>
T castTo(double val) {
    return static_cast<T>(val);
}

// Cannot deduce T from arguments — must be explicit
int    i = castTo<int>(3.99);     // T = int  → i = 3
float  f = castTo<float>(3.99);  // T = float → f = 3.99f

9.4 Multiple Template Parameters

A template can have more than one type parameter, each independently deduced or specified:

template<typename T, typename U>
void printPair(T first, U second) {
    std::cout << "(" << first << ", " << second << ")\n";
}

printPair(42, 3.14);          // T=int, U=double
printPair("hello", true);     // T=const char*, U=bool

9.5 Class Templates

A class template lets you define a generic data structure. The classic example is a Stack<T> that works for any element type: 

template<typename T>
class Stack {
private:
    std::vector<T> data;   // internal storage
public:
    void push(const T& value) { data.push_back(value); }
    void pop()                { data.pop_back(); }
    T&   top()                { return data.back(); }
    bool isEmpty()  const     { return data.empty(); }
    int  size()     const     { return static_cast<int>(data.size()); }
};

// Instantiation — must provide the type argument explicitly
Stack<int>         intStack;
Stack<std::string> strStack;
intStack.push(10);
strStack.push("hello");

9.6 Template Member Functions Defined Outside the Class

When you define a template member function outside the class body, you must repeat the template parameter list on every definition: 

template<typename T>
class Pair {
public:
    T first, second;
    Pair(T a, T b);   // declaration
    void swap();      // declaration
};

// Definition outside — prefix with template<typename T>
template<typename T>
Pair<T>::Pair(T a, T b) : first(a), second(b) {}

template<typename T>
void Pair<T>::swap() {
    T temp = first;
    first  = second;
    second = temp;
}

9.7 Template Specialisation

Sometimes a general template does not work correctly — or efficiently — for a specific type. Full specialisation lets you provide an entirely different implementation for one type: 

// General template
template<typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}

// Full specialisation for const char* — compare strings, not pointers
template<>
const char* maximum<const char*>(const char* a, const char* b) {
    return (std::strcmp(a, b) > 0) ? a : b;
}
Note: template<> (empty parameter list) signals a full specialisation. The type is supplied after the function name: maximum<const char*>.

9.8 Non-Type Template Parameters

Template parameters are not limited to types — they can also be compile-time constant values such as integers. This is used for fixed-size data structures: 

template<typename T, int N>
class Array {
private:
    T data[N];     // N must be a compile-time constant
public:
    int  size()        const { return N; }
    T&   operator[](int i)   { return data[i]; }
    const T& operator[](int i) const { return data[i]; }
};

Array<double, 5> vec;   // stack-allocated, 5 doubles, zero overhead
vec[0] = 3.14;

9.9 Default Template Arguments

Like function default arguments, template parameters can have defaults:

template<typename T, int N = 10>
class Buffer {
    T data[N];
public:
    int capacity() const { return N; }
};

Buffer<int>     buf1;   // N defaults to 10
Buffer<int, 32> buf2;   // N explicitly 32

9.10 Templates and Header Files

The compiler needs the full template definition — not just a declaration — at every point of instantiation. This is why template implementations must live in .h (or .hpp) files, not in separate .cpp files.

Regular function / classTemplate function / class
Declaration in .h, definition in .cpp ✔Both declaration and definition in .h ✔
Compiled once per translation unitInstantiated on demand by the compiler
Why? The compiler generates code for Stack<int> only when it sees Stack<int> used — at that point it needs the full definition to stamp out the concrete class. If the definition is in a .cpp file it compiled earlier, the compiler has already forgotten it.

9.11 Variadic Templates (C++11)

C++11 introduced variadic templates, which accept a variable number of type arguments using the ... (parameter pack) syntax. They power utilities like std::tuple and std::make_unique: 

// Base case — called when pack is empty
void print() { std::cout << '\n'; }

// Recursive variadic template
template<typename T, typename... Rest>
void print(T first, Rest... rest) {
    std::cout << first << ' ';
    print(rest...);   // peel off one argument, recurse
}

print(1, 3.14, "hello", true);   // prints: 1 3.14 hello 1

The sizeof...(Args) operator tells you how many arguments are in a pack at compile time. With C++17 fold expressions, many variadic patterns no longer need recursion.

9.12 SFINAE (Brief Overview)

SFINAE stands for "Substitution Failure Is Not An Error". When the compiler tries to substitute template arguments and the resulting type would be ill-formed, it silently discards that overload candidate instead of producing an error. This lets you write templates that are only available for certain types: 

#include <type_traits>

// Only enabled when T is an arithmetic type (int, float, double…)
template<typename T>
typename std::enable_if<std::is_arithmetic<T>::value, T>::type
square(T x) { return x * x; }

// square("hi") → SFINAE: substitution fails quietly, compiler looks elsewhere

Modern C++ (C++20) replaces most SFINAE patterns with the cleaner Concepts syntax.

9.13 Comparison: Templates vs Overloading vs Inheritance

MechanismResolved atBest used when
Templates Compile time Algorithm or container is type-independent and you want zero-overhead genericity
Function overloading Compile time Small number of known types with meaningfully different implementations
Inheritance / virtual Runtime Behaviour must vary between objects of different types at runtime (runtime polymorphism)

Templates incur no runtime cost but can increase binary size (code bloat) because the compiler emits a separate copy of the function for each distinct type. Virtual dispatch has a small constant runtime overhead (vtable lookup) but produces smaller code.

9.14 Key Takeaways

  • template<typename T> declares T as a placeholder type resolved at compile time.
  • Function templates support type deduction; class templates require explicit type arguments.
  • Use full specialisation (template<>) when a specific type needs different behaviour.
  • Non-type parameters (template<int N>) enable compile-time-fixed data structures.
  • Template implementations must be in header files — the compiler needs the full definition at instantiation.
  • Variadic templates (typename... Args) enable functions and classes with any number of type parameters.
  • SFINAE / Concepts allow constrained templates that only apply to certain types.
