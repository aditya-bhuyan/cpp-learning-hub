Chapter 07 — OOP — Basics

Bundle data and behavior into classes: constructors, destructors, encapsulation, const and static members.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

7.1 What Is Object-Oriented Programming?

So far you have written procedural code: data lives in variables and arrays, and separate functions act on it. Object-Oriented Programming (OOP) bundles the data and the functions that work on that data into a single unit called a class. A variable of a class type is an object (also called an instance). A class is the blueprint; objects are the things built from it.

The four pillars of OOP

PillarIdeaC++ mechanism
EncapsulationHide internal data; expose a small, safe interface.private data + public member functions
AbstractionShow what an object does, hide how.Class interfaces, abstract classes
InheritanceBuild a new class from an existing one and reuse its code.class Derived : public Base (Chapter 08)
PolymorphismTreat different types through a common interface.virtual functions, overloading (Chapter 08)

This chapter focuses on encapsulation and abstraction — the foundation for everything else. Inheritance and polymorphism are covered in Chapter 08.

7.2 Your First Class

#include <iostream>
#include <string>
using namespace std;

class Dog {
public:                          // access specifier (explained in 7.4)
    string name;                 // data member
    int    age;                  // data member

    void bark() const {          // member function
        cout << name << " says Woof!\n";
    }
};                               // <-- the semicolon after the closing brace is REQUIRED

int main() {
    Dog d;                       // create an object (instance) of class Dog
    d.name = "Rex";              // access members with the dot operator
    d.age  = 3;
    d.bark();

    Dog* p = &d;                 // pointer to an object
    cout << p->name << " is " << p->age << "\n";   // arrow operator for pointers
    return 0;
}

Output:

Rex says Woof!
Rex is 3
Do not forget the semicolon A class definition ends with };. Leaving out the semicolon produces confusing errors that often point at the line after the class.

7.3 class vs struct

In C++ the two keywords are almost identical. The only difference is the default access level:

  • class — members are private by default.
  • struct — members are public by default.
class A { int x; };      // x is private by default
struct B { int x; };     // x is public by default

class C { public:   int x; };   // identical to B
struct D { private: int x; };   // identical to A

int main() {
    A a; B b;
    // a.x = 1;     // ERROR: 'x' is private
    b.x = 1;        // OK
    return 0;
}

Convention: use struct for simple passive bundles of data (a point, a pair of values) and class when the type has invariants to protect, private state and behavior. Both can have constructors, member functions and inheritance.

7.4 Access Specifiers

Access specifiers control who may use a member.

SpecifierAccessible from
publicAnywhere — inside the class, derived classes and any outside code.
privateOnly member functions (and friends) of the same class. Not even derived classes.
protectedMember functions (and friends) of the class and of its derived classes. Not outside code.
 
class Account {
public:
    void show() const;       // part of the interface: anyone may call it
protected:
    double rate = 0.02;      // visible to classes derived from Account (Chapter 08)
private:
    double balance = 0.0;    // internal detail: only Account's own functions may touch it
};

int main() {
    Account a;
    a.show();                // OK
    // a.rate    = 0.05;     // ERROR: protected
    // a.balance = 100;      // ERROR: private
    return 0;
}
void Account::show() const {}
Rule of thumb Make data members private and expose only the operations that make sense. This is encapsulation: it lets you change the internals later without breaking code that uses the class.

7.5 Data Members and Member Functions

Data members (fields, attributes) hold the state of each object. Member functions (methods) define its behavior. Each object has its own copy of every non-static data member, while all objects share one copy of each member function's code. A member function can be defined inside the class (implicitly inline) or outside using the scope-resolution operator ::. 

#include <iostream>
using namespace std;

class Point {
private:
    int x = 0;                    // default member initializers (C++11)
    int y = 0;

public:
    void set(int newX, int newY);       // declaration only
    int  getX() const { return x; }     // defined inside the class
    int  getY() const { return y; }
};

// Defined outside the class: ClassName::functionName
void Point::set(int newX, int newY) {
    x = newX;                     // x and y refer to THIS object's members
    y = newY;
}

int main() {
    Point p1, p2;
    p1.set(1, 2);
    p2.set(10, 20);               // p2 has its own x and y
    cout << p1.getX() << "," << p1.getY() << "  "
         << p2.getX() << "," << p2.getY() << "\n";
    return 0;
}

Output:

1,2  10,20

7.6 The this Pointer

Inside every non-static member function, C++ provides a hidden pointer named this that points to the object the function was called on. When you write x inside a member function, the compiler treats it as this->x. Its type is ClassName* (or const ClassName* inside a const member function).

Common uses: disambiguating a parameter that has the same name as a member, and returning the object itself to allow method chaining.

#include <iostream>
using namespace std;

class Box {
private:
    int w = 0, h = 0;

public:
    // Parameter names equal member names: this-> tells them apart.
    Box& setWidth(int w)  { this->w = w; return *this; }   // *this = the object itself
    Box& setHeight(int h) { this->h = h; return *this; }

    void print() const {
        cout << "Box " << w << "x" << h << "\n";
    }
};

int main() {
    Box b;
    b.setWidth(4).setHeight(7);      // chaining: each call returns the same object
    cout << "same object: " << (&b == &b.setWidth(4)) << "\n";   // setWidth returns *this
    b.print();
    return 0;
}

Output:

same object: 1
Box 4x7

7.7 Constructors

A constructor is a special member function that runs automatically when an object is created. It has the same name as the class and no return type. Its job is to put the new object into a valid state.

Default constructor

Takes no arguments. If you declare no constructors at all, the compiler generates one for you — but it leaves built-in members (int, double…) uninitialized. As soon as you declare any other constructor, the compiler no longer generates the default one (add it yourself, or write Foo() = default;).

Parameterized constructor

Takes arguments so each object can be created with its own initial values. Constructors can be overloaded.

Copy constructor

ClassName(const ClassName& other) creates a new object as a copy of an existing one. It runs when you initialize from another object (Foo b = a; or Foo b(a);), pass an object by value to a function, or return one by value (unless the compiler elides the copy). If you do not write one, the compiler provides a memberwise copy — fine for plain values, dangerous for classes that own raw pointers (see Chapter 12). 

#include <iostream>
#include <string>
using namespace std;

class Person {
private:
    string name;
    int    age;

public:
    // 1. Default constructor
    Person() : name("Unknown"), age(0) {
        cout << "default ctor\n";
    }

    // 2. Parameterized constructor
    Person(const string& n, int a) : name(n), age(a) {
        cout << "param ctor: " << name << "\n";
    }

    // 3. Copy constructor
    Person(const Person& other) : name(other.name), age(other.age) {
        cout << "copy ctor: " << name << "\n";
    }

    void print() const { cout << name << " (" << age << ")\n"; }
};

void byValue(Person p) { p.print(); }       // parameter is a COPY -> copy ctor runs

int main() {
    Person a;                    // default ctor
    Person b("Ada", 36);         // parameterized ctor
    Person c = b;                // copy ctor
    Person d(b);                 // copy ctor (direct-init syntax)
    byValue(b);                  // copy ctor (pass by value)
    a.print();
    return 0;
}

Output:

default ctor
param ctor: Ada
copy ctor: Ada
copy ctor: Ada
copy ctor: Ada
Ada (36)
Unknown (0)
The "most vexing parse" Person x(); does not create an object — it declares a function named x returning Person. To use the default constructor, write Person x; or Person x{};.

7.8 Initialization List vs Assignment in the Body

There are two ways to give members their starting values: 

class Demo {
    int           a;
    const int     b;     // const member
    int&          r;     // reference member
    std::string   s;

public:
    // (1) INITIALIZATION LIST: members are constructed directly with these values
    Demo(int x, int& ref) : a(x), b(x * 2), r(ref), s("hi") {}

    // (2) ASSIGNMENT IN THE BODY: members are first default-constructed, then assigned
    // Demo(int x, int& ref) {
    //     a = x;          // OK, but redundant work for class types
    //     b = x * 2;      // ERROR: cannot assign to a const member
    //     r = ref;        // ERROR: a reference must be bound at initialization
    //     s = "hi";       // s was default-constructed to "" and then reassigned
    // }
};
Initialization listAssignment in body
When it happensBefore the constructor body runsInside the body, after members already exist
const / reference membersRequired — the only optionCompile error
Members without a default constructorRequiredCompile error
Efficiency for class-type membersOne step: construct with the valueTwo steps: default-construct, then assign
Initialization order Members are initialized in the order they are declared in the class, not the order written in the list. Compile with -Wall to get a warning (-Wreorder) when the two differ.

7.9 Destructors

A destructor is the mirror image of a constructor: ~ClassName(), no parameters, no return type, and only one per class. It runs automatically when the object's lifetime ends:

  • a stack (automatic) object goes out of scope — destructors run in reverse order of construction;
  • a heap object is destroyed with delete (not when the pointer variable goes out of scope!);
  • a global/static object is destroyed when the program ends;
  • a temporary object is destroyed at the end of the full expression.

Responsibility: release anything the object acquired — memory from new, open files, locks, network connections. If your class owns no such resources, you usually do not need to write a destructor at all. 

#include <iostream>
using namespace std;

class Tracer {
    const char* label;
public:
    Tracer(const char* l) : label(l) { cout << "  construct " << label << "\n"; }
    ~Tracer()                        { cout << "  destruct  " << label << "\n"; }
};

int main() {
    cout << "enter main\n";
    Tracer a("a");
    {
        cout << "enter inner block\n";
        Tracer b("b");
    }                                   // b destroyed here
    cout << "left inner block\n";

    Tracer* p = new Tracer("heap");     // lives until delete
    delete p;                           // destructor runs NOW

    cout << "leave main\n";
    return 0;
}                                       // a destroyed here

Output:

enter main
  construct a
enter inner block
  construct b
  destruct  b
left inner block
  construct heap
  destruct  heap
leave main
  destruct  a

7.10 const Member Functions

Putting const after a member function's parameter list promises that the function will not modify the object's (non-mutable) data members. Inside it, this has type const ClassName*, so any attempt to change a member is a compile error.

This matters because a const object (or a reference/pointer-to-const, such as const Foo& parameters) can only call const member functions. 

#include <iostream>
using namespace std;

class Counter {
    int value = 0;
    mutable int readCount = 0;     // 'mutable': may change even in const functions

public:
    void increment() { ++value; }                 // modifies state: NOT const

    int get() const {                             // only reads state: const
        ++readCount;                              // OK because it is mutable
        // ++value;                               // ERROR: cannot modify in a const function
        return value;
    }
    int reads() const { return readCount; }
};

void report(const Counter& c) {      // c is const: only const members are callable
    cout << "value = " << c.get() << "\n";
    // c.increment();                // ERROR: increment() is not const
}

int main() {
    Counter c;
    c.increment();
    c.increment();
    report(c);
    cout << "reads = " << c.reads() << "\n";
    return 0;
}

Output:

value = 2
reads = 1
Make everything const that can be Getters, display(), area() and similar query functions should all be const. It documents intent, lets the compiler catch accidental modification, and allows use with const objects.

7.11 Static Members

A static data member belongs to the class, not to any one object: there is exactly one copy, shared by all instances. A static member function has no this pointer, so it can access only static members — but it can be called without an object, as ClassName::function(). 

#include <iostream>
using namespace std;

class Widget {
private:
    static int count;            // declaration: one shared variable
    int id;

public:
    Widget()  : id(++count) {}
    ~Widget() { --count; }

    int getId() const { return id; }
    static int getCount() { return count; }     // static function: no 'this'
};

int Widget::count = 0;           // definition (required once, in ONE .cpp file)

int main() {
    cout << "start: " << Widget::getCount() << "\n";    // call with no object
    Widget a, b, c;
    cout << "after 3: " << Widget::getCount() << "\n";
    cout << "c.id = " << c.getId() << "\n";
    return 0;
}

Output:

start: 0
after 3: 3
c.id = 3

Since C++17 you may write inline static int count = 0; inside the class and skip the separate definition. A static const int (or constexpr) of integral type can be initialized right in the class.

7.12 Friend Functions and Friend Classes

A friend is a function or class that the class grants permission to access its private and protected members. A friend is not a member: it has no this pointer and is not affected by access specifiers. Friendship is granted (never taken), is not mutual, and is not inherited. 

#include <iostream>
using namespace std;

class Vault;                                  // forward declaration

class Auditor {                               // will be a friend CLASS of Vault
public:
    void inspect(const Vault& v) const;
};

class Vault {
private:
    int gold = 42;

    friend void peek(const Vault& v);         // friend FUNCTION
    friend class Auditor;                     // friend CLASS: all its members get access
};

void peek(const Vault& v) {                   // ordinary function, but a friend
    cout << "peek sees " << v.gold << "\n";
}

void Auditor::inspect(const Vault& v) const {
    cout << "auditor counts " << v.gold << "\n";
}

int main() {
    Vault v;
    peek(v);
    Auditor().inspect(v);
    // cout << v.gold;    // ERROR: main() is not a friend
    return 0;
}

Output:

peek sees 42
auditor counts 42
Use friends sparingly Every friend weakens encapsulation. The classic legitimate use is an operator<< for printing objects with cout (covered with operator overloading); otherwise prefer public member functions.

7.13 Getters and Setters — The Encapsulation Pattern

With private data, outside code reaches the data only through public getters (accessors, usually const) and setters (mutators). The payoff is that setters can validate input, so the object can never be in an invalid state. 

#include <iostream>
using namespace std;

class Thermostat {
private:
    double target = 20.0;                 // invariant: always within [5, 30]

public:
    double getTarget() const { return target; }          // getter

    bool setTarget(double t) {                           // setter with validation
        if (t < 5.0 || t > 30.0) return false;           // reject invalid values
        target = t;
        return true;
    }
};

int main() {
    Thermostat t;
    cout << t.setTarget(22.5) << " -> " << t.getTarget() << "\n";
    cout << t.setTarget(99.0) << " -> " << t.getTarget() << "\n";   // rejected, unchanged
    return 0;
}

Output:

1 -> 22.5
0 -> 22.5
Do not add getters/setters blindly A setter that does no validation and a getter for every field simply re-exposes the data. Provide accessors only for what users of the class genuinely need, and prefer meaningful operations (deposit(), withdraw()) over raw setBalance().

7.14 Creating Objects: Stack vs Heap

Stack (automatic)Heap (dynamic)
SyntaxDog d("Rex");Dog* p = new Dog("Rex");
Member accessd.bark()p->bark() or (*p).bark()
LifetimeUntil the end of the enclosing scopeUntil you call delete p;
Destructor runsAutomatically at scope exitOnly when delete is called
Speed / sizeVery fast; limited stack spaceSlower allocation; large and flexible
RiskLowLeaks, double delete, dangling pointers
 
#include <iostream>
#include <string>
using namespace std;

class Dog {
    string name;
public:
    Dog(const string& n) : name(n) { cout << name << " created\n"; }
    ~Dog()                         { cout << name << " destroyed\n"; }
    void bark() const              { cout << name << ": Woof!\n"; }
};

int main() {
    Dog onStack("Stacky");          // automatic: destroyed at the closing brace of main
    onStack.bark();

    Dog* onHeap = new Dog("Heapy"); // dynamic: YOU must delete it
    onHeap->bark();                 // arrow operator through the pointer
    delete onHeap;                  // runs ~Dog(), then frees memory
    onHeap = nullptr;               // avoid a dangling pointer

    Dog* arr = new Dog[2]{Dog("A"), Dog("B")};   // array of objects on the heap
    delete[] arr;                   // arrays need delete[]  (NOT plain delete)
    return 0;
}

Output:

Stacky created
Stacky: Woof!
Heapy created
Heapy: Woof!
Heapy destroyed
A created
B created
B destroyed
A destroyed
Stacky destroyed
Every new needs exactly one delete Forgetting it leaks memory; deleting twice is undefined behavior; using the pointer after delete is a dangling-pointer bug. Prefer stack objects by default. When you truly need heap allocation, modern C++ offers std::unique_ptr and std::make_unique (Chapter 12), which call delete for you.

7.15 Separating Declaration (.h) from Implementation (.cpp)

Real projects split a class into a header (the declaration — the interface other files need) and a source file (the definitions of the member functions). Other files #include only the header.

Rectangle.h — declaration:

#ifndef RECTANGLE_H        // include guard: prevents double inclusion
#define RECTANGLE_H

class Rectangle {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h);     // declarations only
    double area() const;
    double perimeter() const;
};

#endif

Rectangle.cpp — implementation:

#include "Rectangle.h"           // quotes: a header of your own project

Rectangle::Rectangle(double w, double h) : width(w), height(h) {}   // note Rectangle::
double Rectangle::area() const      { return width * height; }       // keep 'const'!
double Rectangle::perimeter() const { return 2 * (width + height); }

main.cpp — user of the class:

#include <iostream>
#include "Rectangle.h"

int main() {
    Rectangle r(3, 4);
    std::cout << r.area() << "\n";    // 12
    return 0;
}

Build by compiling all the .cpp files together:

g++ -std=c++17 -Wall -o app main.cpp Rectangle.cpp
./app
  • Use an include guard (#ifndef/#define/#endif, or #pragma once) in every header.
  • Avoid using namespace std; in headers — it forces that choice on every file that includes them.
  • The const in a member function's signature must appear in both the declaration and the definition.
  • Short functions may stay in the header, defined inside the class body (implicitly inline).

7.16 Key Takeaways

  • OOP bundles data and behavior into classes; its four pillars are encapsulation, abstraction, inheritance and polymorphism.
  • class and struct differ only in default access: private vs public.
  • private hides internals, public is the interface, protected also allows derived classes.
  • this is a hidden pointer to the current object; x in a member function means this->x.
  • Constructors initialize objects: default, parameterized and copy. Declaring any constructor suppresses the implicit default one.
  • Use the initialization list — it is required for const and reference members and avoids needless assignment.
  • The destructor runs when a stack object leaves scope or when a heap object is deleted; it releases the object's resources.
  • Mark query functions const; const objects can call only const member functions.
  • static members are shared by the whole class and are defined once outside it (before C++17).
  • friend grants access to private members — use it rarely.
  • Getters/setters let you validate data and keep invariants; do not expose every field automatically.
  • Prefer stack objects; every new must be matched by delete (delete[] for arrays).
  • Put declarations in .h files (with include guards) and definitions in .cpp files.
