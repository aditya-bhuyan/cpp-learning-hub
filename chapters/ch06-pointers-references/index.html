Chapter 06 — Pointers & References

Master memory addresses, pointer arithmetic, references, and the common pitfalls every C++ programmer must know.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

6.1 What is a Pointer?

Every variable lives at a specific location in memory. A pointer is a variable whose value is a memory address — it literally points to where another value is stored. Pointers are the foundation of dynamic memory, data structures, and low-level system programming in C++.

Two fundamental operators work hand-in-hand with pointers:

  • Address-of operator & — placed before a variable name, it yields the address of that variable.
  • Dereference operator * — placed before a pointer variable, it yields the value at the address stored in the pointer.
#include <iostream>
using namespace std;

int main() {
    int x = 42;
    int* p = &x;        // p holds the address of x

    cout << "Value of x:       " << x  << "\n";   // 42
    cout << "Address of x (&x):" << &x << "\n";   // e.g. 0x7ffee4b2c8ac
    cout << "Value stored in p:" << p  << "\n";   // same address
    cout << "Value pointed to: " << *p << "\n";   // 42  (dereference)

    *p = 100;   // write through the pointer
    cout << "x is now: " << x << "\n";            // 100
    return 0;
}

6.2 Pointer Declaration Syntax

The asterisk * in a declaration belongs to the variable name, not to the type — even though the popular style int* p visually suggests it belongs to the type. Both int* p and int *p are legal; the community is split, but many modern style guides (Google, LLVM) place * next to the type when declaring one pointer per line. 

int* p;          // recommended when one pointer per declaration
int *q;          // also valid — traditional C style
int* a, b;       // GOTCHA: only 'a' is a pointer; 'b' is a plain int!
int *c, *d;      // both c and d are pointers — unambiguous
Convention To avoid the int* a, b trap, declare one variable per line, or always write int *a, *b; when declaring multiple pointers together.

6.3 nullptr — The Safe Null Pointer

A pointer that does not point to any valid object should be set to nullptr (introduced in C++11). It is type-safe and unambiguous, unlike the older NULL macro (which is just 0 or (void*)0) or the literal 0. 

int* p = nullptr;   // safe null pointer (C++11+)

if (p != nullptr) {
    cout << *p;     // only dereference when non-null
}

// Why not NULL or 0?
// NULL is a macro — it expands to 0 (an integer), causing ambiguity in overloads.
// nullptr has type std::nullptr_t, so overload resolution is unambiguous.
Rule Always initialise pointers. If you have no valid address yet, use nullptr. Dereferencing a null pointer is undefined behaviour and will crash at runtime.

6.4 Pointer Arithmetic

Arithmetic on pointers moves the address by multiples of the pointed-to type's size. Adding 1 to an int* advances the address by sizeof(int) bytes (typically 4), not by 1 byte. 

int arr[] = {10, 20, 30, 40, 50};
int* p = arr;           // points to arr[0]

cout << *p     << "\n";  // 10
cout << *(p+1) << "\n";  // 20
cout << *(p+4) << "\n";  // 50

p++;                    // now points to arr[1]
cout << *p     << "\n";  // 20

// Subscript equivalence: arr[i]  ==  *(arr + i)
cout << arr[3] << " == " << *(arr + 3) << "\n";  // 40 == 40

Pointer subtraction gives the number of elements between two pointers of the same type. Comparing pointers with <, >, == is valid only when both pointers refer into the same array (or one past its end).

6.5 Pointers and Arrays

In C++, the name of an array decays to a pointer to its first element in most expressions. Therefore arr and &arr[0] yield the same address. 

int arr[5] = {1, 2, 3, 4, 5};

// arr and &arr[0] are the same address
cout << (arr == &arr[0]) << "\n";   // 1 (true)

// Pointer-based traversal
for (int* p = arr; p != arr + 5; ++p) {
    cout << *p << " ";   // 1 2 3 4 5
}
cout << "\n";
Note: &arr (address of the whole array) has type int (*)[5] — different from arr (type int*). They hold the same numeric address but arithmetic on them behaves differently.

6.6 Pointers to Pointers

A pointer can itself be pointed to. int** is a pointer to a pointer to int. This is commonly used to implement functions that modify a pointer, build 2-D dynamic arrays, or pass arrays of strings (like char** argv). 

int  x  = 7;
int* p  = &x;    // p  points to x
int** pp = &p;   // pp points to p

cout << **pp << "\n";   // 7  (double dereference)

**pp = 99;               // modifies x via pp
cout << x << "\n";      // 99

6.7 const Pointers

The keyword const can appear in two positions relative to the *, producing four distinct combinations:

DeclarationPointer is const?Pointed-to value is const?
int* pNoNo
const int* pNoYes — cannot modify *p
int* const pYes — cannot reseat pNo
const int* const pYesYes — fully immutable
 
int a = 10, b = 20;

const int* pc = &a;   // pointer-to-const: cannot change *pc
// *pc = 5;           // ERROR
pc = &b;              // OK — the pointer itself can change

int* const cp = &a;   // const-pointer: pointer address is fixed
*cp = 5;              // OK — can change the pointed-to value
// cp = &b;           // ERROR

const int* const ccp = &a;  // both fixed
// *ccp = 5;          // ERROR
// ccp = &b;          // ERROR
Reading trick: read the declaration right-to-left. int* const p → "p is a const pointer to int". const int* p → "p is a pointer to const int".

6.8 References

A reference is an alias — an alternative name for an existing variable. It is declared with & after the type and must be initialised at the point of declaration. Unlike a pointer, a reference cannot be reseated: once bound, it always refers to the same object. 

int x = 10;
int& ref = x;    // ref is an alias for x

ref = 20;        // same as x = 20
cout << x << "\n";  // 20

// A reference to const allows binding temporaries and rvalues
const int& cref = 42;   // extends the lifetime of the temporary
cout << cref << "\n";   // 42

References are particularly useful as function parameters — they avoid copying large objects and allow functions to modify the caller's variables without the syntactic noise of pointers.

6.9 Pass by Pointer vs Pass by Reference

AspectPass by PointerPass by Reference
Syntax at call sitef(&x)f(x)
Can be null?Yes — caller may pass nullptrNo — must bind to a valid object
Reseating inside functionYes — pointer can be pointed elsewhereNo — always the same object
Preferred useOptional parameters, dynamic memory, C-style APIsIn/out parameters, avoiding copies
 
void doubleByPtr(int* p) { *p *= 2; }
void doubleByRef(int& r) {  r *= 2; }

int n = 5;
doubleByPtr(&n);   // n = 10
doubleByRef(n);    // n = 20

6.10 Returning Pointers and References

Never return a pointer or reference to a local variable — the variable is destroyed when the function returns, leaving a dangling pointer/reference. This is undefined behaviour. 

// DANGER — dangling pointer
int* bad() {
    int local = 5;
    return &local;   // local is destroyed on return!
}

// SAFE — return pointer to static or heap-allocated data
int* good() {
    static int val = 42;
    return &val;     // static storage lasts the lifetime of the program
}

// SAFE — return reference to a parameter that outlives the call
int& maxRef(int& a, int& b) {
    return (a >= b) ? a : b;
}

6.11 Void Pointers

A void* is a generic pointer that can hold the address of any type. It cannot be dereferenced directly — you must cast it to the correct pointer type first. void* is used in low-level APIs (e.g., memcpy, malloc) but should be avoided in modern C++ in favour of templates or std::any. 

int  x = 42;
void* vp = &x;         // store address of int in void*

// *vp;                // ERROR — cannot dereference void*
int* ip = static_cast<int*>(vp);
cout << *ip << "\n";   // 42

6.12 Dynamic Memory with new / delete

The new operator allocates memory on the heap at runtime and returns a pointer to it. The memory persists until explicitly freed with delete. A full treatment including smart pointers (unique_ptr, shared_ptr) is covered in Chapter 12 — Memory Management. 

#include <iostream>
using namespace std;

int main() {
    int* p = new int(7);       // allocate one int on the heap
    cout << *p << "\n";        // 7
    delete p;                  // free the memory
    p = nullptr;               // avoid dangling pointer

    int* arr = new int[5]{1,2,3,4,5};   // heap array
    cout << arr[2] << "\n";    // 3
    delete[] arr;              // must use delete[] for arrays
    arr = nullptr;
    return 0;
}
Modern C++: Prefer std::unique_ptr and std::shared_ptr over raw new/delete. They automatically release memory when they go out of scope, eliminating entire classes of bugs.

6.13 Common Pointer Bugs

BugDescriptionHow to Avoid
Dangling pointerPointer to freed or out-of-scope memorySet pointer to nullptr after deletion; use smart pointers
Memory leakHeap memory allocated but never freedMatch every new with delete; prefer RAII / smart pointers
Double deleteCalling delete twice on the same pointerSet to nullptr after delete; use unique_ptr
Wild (uninitialised) pointerPointer declared but never assigned an addressAlways initialise pointers to nullptr or a valid address
Buffer overrunPointer arithmetic goes past array boundsTrack size explicitly; use std::array / std::vector
 
// Wild pointer — UNDEFINED BEHAVIOUR
int* wild;          // uninitialised; holds garbage address
// *wild = 5;       // crash or silent corruption

// Dangling pointer — UNDEFINED BEHAVIOUR
int* dp = new int(10);
delete dp;
// cout << *dp;     // dp now dangles — do NOT use
dp = nullptr;       // safe

// Double delete — UNDEFINED BEHAVIOUR
int* x = new int(3);
delete x;
// delete x;        // ERROR: already freed
x = nullptr;

6.14 Key Takeaways

  • &var gives the address of var; *ptr gives the value at the address in ptr.
  • Always initialise pointers — use nullptr when no valid address is available.
  • Pointer arithmetic moves by multiples of the element size; arr[i] is exactly *(arr + i).
  • const int* p = pointer to const (value immutable); int* const p = const pointer (address immutable).
  • References must be initialised and cannot be reseated — prefer them over pointers for in/out parameters.
  • Never return a pointer or reference to a local variable.
  • For heap memory in modern C++, prefer smart pointers over raw new/delete.
