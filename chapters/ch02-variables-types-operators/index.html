Chapter 02 — Variables, Types & Operators

How C++ stores data, converts between types, and combines values with operators.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

2.1 Fundamental Data Types

C++ is statically typed: every variable has a type that is fixed at compile time. The type determines how much memory the variable occupies, which values it can hold, and which operations are legal. The language provides a small set of built-in fundamental types:

TypePurposeTypical sizeTypical range
boolTruth value (true / false)1 bytefalse or true
charA single character / small integer1 byte-128 to 127 (or 0 to 255)
shortSmall integer2 bytes-32,768 to 32,767
intDefault integer type4 bytes-2,147,483,648 to 2,147,483,647
longLarger integer4 bytes (Windows) / 8 bytes (Linux, macOS)at least 32 bits
long long64-bit integer (C++11)8 bytesabout ±9.22 × 1018
floatSingle-precision floating point4 bytesabout 6–7 significant digits

Sizes are not fixed by the standard The C++ standard only guarantees minimums and the ordering sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long). The numbers in this chapter describe typical 64-bit desktop systems. When you need an exact width, use the fixed-width types from <cstdint> such as int32_t and uint64_t.

Integer types

int      age     = 30;            // everyday whole numbers
short    year    = 2024;          // small range, saves memory in big arrays
long     pop     = 8000000000L;   // suffix L marks a long literal
long long huge   = 9000000000000LL;

char     grade   = 'A';           // single quotes: one character
std::cout << grade << " has code " << static_cast<int>(grade);   // A has code 65

Floating-point types

float  f = 3.14159f;     // suffix f: float literal (without it the literal is a double)
double d = 3.141592653589793;
double sci = 6.022e23;   // scientific notation: 6.022 × 10^23

std::cout << (0.1 + 0.2 == 0.3);   // prints 0 (false!) - binary floating point is approximate
Tip — never compare floating-point numbers with == Values such as 0.1 cannot be represented exactly in binary. Compare with a tolerance instead: std::abs(a - b) < 1e-9. Prefer double over float unless memory or GPU data layout forces your hand.

bool and void

bool isReady = true;
bool hasError = false;
std::cout << isReady;                      // prints 1
std::cout << std::boolalpha << isReady;    // prints true

int  x = 5;
bool nonZero = x;      // any non-zero value converts to true; 0 converts to false

void log(const std::string& msg);   // void as a return type: the function returns nothing
// void v;             // ERROR: you cannot declare a variable of type void

void appears in two main roles: as a function return type meaning "returns nothing", and in void*, a generic pointer type you will meet in Chapter 06.

2.2 The sizeof Operator

sizeof yields the size in bytes of a type or of an expression's type, as a value of type std::size_t (an unsigned integer). It is evaluated at compile time and never evaluates its operand. 

#include <iostream>
int main() {
    std::cout << sizeof(int)         << '\n';   // 4
    std::cout << sizeof(double)      << '\n';   // 8
    std::cout << sizeof(char)        << '\n';   // 1 (always, by definition)

    int n = 10;
    std::cout << sizeof n            << '\n';   // 4 - parentheses optional for expressions
    int arr[10];
    std::cout << sizeof(arr)         << '\n';   // 40 = 10 elements × 4 bytes
    std::cout << sizeof(arr) / sizeof(arr[0]) << '\n';   // 10 = element count
}
Memory unitValue
1 byte8 bits (CHAR_BIT from <climits>)
n bitscan represent 2n distinct values
32-bit unsigned0 … 232 − 1 = 4,294,967,295
32-bit signed (two's complement)−231 … 231 − 1

To query exact limits use <limits>: std::numeric_limits<int>::max(), or the C-style macros INT_MAX, UINT_MAX from <climits>.

2.3 Declaring and Initializing Variables

A declaration introduces a name and a type. A definition also reserves storage. An initialization gives the variable its first value.

int a;            // declared, but UNINITIALIZED - holds garbage (undefined behaviour to read)
int b = 5;        // copy initialization
int c(5);         // direct initialization
int d{5};         // brace (uniform) initialization - C++11, preferred
int e{};          // empty braces: value-initialized to 0
auto f = 5;       // type deduced from the initializer: int
auto g = 2.5;     // double

int x = 1, y = 2, z = 3;   // several variables in one declaration
Tip — prefer brace initialization Braces refuse narrowing conversions at compile time: int n{3.7}; is an error, whereas int n = 3.7; silently truncates to 3. Always initialize local variables — reading an uninitialized local is undefined behaviour.

Literals and suffixes

int      dec  = 42;          // decimal
int      hex  = 0x2A;        // hexadecimal (42)
int      oct  = 052;         // octal (42) - a leading 0 means octal!
int      bin  = 0b101010;    // binary literal (C++14) (42)
int      big  = 1'000'000;   // digit separator (C++14)
unsigned u    = 42u;         // u  = unsigned
long long ll  = 42LL;        // LL = long long
float    f    = 1.5f;        // f  = float
char     ch   = '\n';        // escape sequences: \n \t \\ \' \" \0

Naming rules

  • Names may contain letters, digits, and underscores, and must not start with a digit.
  • Names are case-sensitive: count, Count and COUNT are three different identifiers.
  • Keywords (int, class, return, …) cannot be used as names.
  • Avoid names that begin with an underscore followed by a capital letter, or that contain a double underscore — they are reserved for the implementation.
  • Choose meaningful names (studentCount, not sc) and stick to one convention such as camelCase or snake_case.
int  total_score;     // valid
int  _internal;       // valid (but avoid leading underscores)
int  2fast;           // ERROR: starts with a digit
int  my-var;          // ERROR: '-' is the subtraction operator
int  class;           // ERROR: keyword

2.4 Type Modifiers: signed, unsigned, short, long

Modifiers adjust the size or sign of a base integer type. An unsigned type spends the sign bit on magnitude, doubling the largest positive value but giving up negative numbers.

unsigned int  items = 0;
items = items - 1;            // WRAPS AROUND to 4294967295, no error is reported!

signed char   sc = -5;
unsigned char uc = 250;
uc = uc + 10;                 // 260 does not fit: wraps to 4
Overflow rules differ Unsigned overflow is well defined: the value wraps modulo 2n. Signed overflow (e.g. INT_MAX + 1) is undefined behaviour — the compiler may assume it never happens and produce surprising code. Use a wider type, or check before you add.

2.5 Type Conversion (Casting)

Implicit conversion

The compiler converts automatically when types are mixed in an expression or assignment.

  • Widening (promotion) goes to a type that can hold every value of the source: int → long, int → double, char → int. This is safe.
  • Narrowing goes to a type that may be unable to hold the value: double → int (fraction discarded), int → short (high bits lost), int → char. This may lose information.
int    i = 42;
double d = i;          // widening: 42 -> 42.0, safe

double pi = 3.99;
int    t = pi;         // narrowing: fractional part is TRUNCATED -> 3 (not 4)

int    big = 70000;
short  s   = big;      // narrowing: 70000 does not fit in 16 bits -> 4464

char   c = 'A';
int    code = c + 1;   // char is promoted to int before the addition: 66

When a binary operator receives operands of different types, the "usual arithmetic conversions" bring both to a common type: roughly int → unsigned → long → unsigned long → long long → float → double → long double. Anything smaller than int is first promoted to int.

Signed/unsigned mix-ups In -1 < 1u the -1 is converted to unsigned (4,294,967,295), so the comparison is false. Compile with -Wall -Wextra to receive -Wsign-compare warnings.

Explicit conversion

Use an explicit cast to document that a conversion is intentional.

double pi = 3.99;

int a = static_cast<int>(pi);        // C++ style: preferred, searchable, checked by the compiler
int b = (int)pi;                     // C-style cast: works but can silently do dangerous things
int c = int(pi);                     // functional cast: same as above

int sum = 17, count = 4;
double bad  = sum / count;                       // 4.0   - integer division happened first!
double good = static_cast<double>(sum) / count;  // 4.25 - one operand is double, so the division is floating
CastUse for
static_cast<T>(x)Well-defined conversions between related types (numeric, enum, base/derived pointers)
const_cast<T>(x)Adding or removing const (rarely justified)
reinterpret_cast<T>(x)Reinterpreting raw bit patterns (low-level, dangerous)
dynamic_cast<T>(x)Safe polymorphic down-casts (Chapter 08)
(T)xC-style: tries all of the above in order — avoid in C++
Tip — why prefer static_cast? The C-style cast (T)x will happily act as a reinterpret_cast or strip const if that is what it takes to compile. static_cast only performs conversions that make sense, and its verbose syntax is easy to grep for during code review.

2.6 Constants

Values that must never change should be declared constant so that the compiler enforces it.

const double PI = 3.14159265358979;   // runtime-or-compile-time constant
constexpr int MAX_USERS = 100;        // guaranteed compile-time constant
#define LEGACY_MAX 100                // preprocessor macro (C heritage)

// PI = 3.0;          // ERROR: assignment of read-only variable

constexpr int square(int n) { return n * n; }
constexpr int AREA = square(12);      // computed by the compiler: 144
int table[MAX_USERS];                 // OK: array sizes need compile-time constants
Featureconstconstexpr#define
Has a typeYesYesNo — plain text substitution
Obeys scope rulesYesYesNo — global from the point of definition
Value known at compile timeOnly if initialized with a constantAlways (enforced)Yes (it is text)
Visible in the debuggerYesYesNo — replaced before compilation
Can be a functionNoYesMacro only (error-prone)

Why const / constexpr beat #define

#define SQUARE(x) x * x
int r = SQUARE(2 + 3);     // expands to 2 + 3 * 2 + 3 = 11, NOT 25!

constexpr int square(int x) { return x * x; }
int s = square(2 + 3);     // 25: the argument is evaluated first
Rule of thumb Use constexpr for values known at compile time, const for values that are set once at runtime (e.g. const int n = readFromUser();), and reserve #define for include guards and conditional compilation. Constants have types, scope and debugger visibility; macros have none of these.

2.7 Arithmetic Operators

OperatorMeaningExampleResult
+Addition7 + 29

*Multiplication7 * 214
/Division7 / 2 and 7.0 / 23 and 3.5
%Remainder (modulo) — integers only7 % 21
The integer division gotcha When both operands are integers, / performs integer division and discards the fraction: 7 / 2 is 3, not 3.5. Assigning the result to a double does not help, because the division has already happened. Make at least one operand floating-point: 7.0 / 2 or static_cast<double>(7) / 2. 
int    a = 7, b = 2;
double wrong = a / b;                      // 3.0
double right = static_cast<double>(a) / b; // 3.5

std::cout <<  7 % 3 << '\n';   //  1
std::cout << -7 / 2 << '\n';   // -3  (truncates toward zero since C++11)
std::cout << -7 % 2 << '\n';   // -1  (sign of the result follows the dividend)

// int z = 5 / 0;    // undefined behaviour for integers
// 5.0 / 0.0         // floating point gives inf (IEEE 754)
// For a floating-point remainder use std::fmod(7.5, 2.0) from <cmath> -> 1.5

Common use of %: wrapping an index (i % size), testing divisibility (n % 3 == 0), and extracting digits (n % 10 is the last digit).

2.8 Comparison (Relational) Operators

Comparison operators yield a bool.

= is not == if (x = 5) assigns 5 to x and is always true. The compiler warns with -Wall. Likewise 1 < x < 10 does not mean "x between 1 and 10" — write 1 < x && x < 10.

int age = 25;
bool hasTicket = true;

bool canEnter = (age >= 18) && hasTicket;          // both must hold
bool needsHelp = (age < 12) || (age > 65);           // either is enough
bool isMinor = !(age >= 18);                          // negation

// Short-circuit evaluation: the right operand is skipped when the result is already known
int d = 0;
bool safe = (d != 0) && (10 / d > 1);   // 10 / d is never evaluated - no division by zero
Tip — short-circuiting Put the cheap or guarding condition first. ptr != nullptr && ptr->value > 0 is safe precisely because && stops as soon as the left side is false.

2.10 Bitwise Operators

Bitwise operators work on the individual bits of integer operands. They are essential in embedded systems, graphics, networking, flags/permissions, and performance-sensitive code.

OperatorNameRuleExample (a = 12 = 1100, b = 10 = 1010)
&AND1 only if both bits are 1a & b = 1000 = 8
|OR1 if either bit is 1a | b = 1110 = 14
^XOR1 if the bits differa ^ b = 0110 = 6
~NOT (complement)flips every bit~a (low 8 bits) = 11110011
<<Left shiftshift left, fill with 0 (× 2n)a << 2 = 110000 = 48
>>Right shiftshift right (÷ 2n)a >> 2 = 0011 = 3
 
#include <bitset>
unsigned int a = 12, b = 10;

std::cout << std::bitset<8>(a & b) << '\n';   // 00001000
std::cout << std::bitset<8>(a | b) << '\n';   // 00001110
std::cout << std::bitset<8>(a ^ b) << '\n';   // 00000110
std::cout << std::bitset<8>(~a)    << '\n';   // 11110011
std::cout << (a << 2) << ' ' << (a >> 2) << '\n';   // 48 3

Practical bit tricks

// Is n odd?  The lowest bit of an odd number is always 1.
bool odd = (n & 1) != 0;

// Bit manipulation with a mask (bit positions count from 0 at the right)
n |=  (1u << k);     // SET    bit k
n &= ~(1u << k);     // CLEAR  bit k
n ^=  (1u << k);     // TOGGLE bit k
bool on = (n >> k) & 1u;   // TEST   bit k

// XOR swap (no temporary):  a ^= b;  b ^= a;  a ^= b;
Do not confuse & with &&, or | with || 5 & 2 is the bitwise value 0, while 5 && 2 is the logical value true. Also, right-shifting a negative signed number is implementation-defined (usually arithmetic shift), so use unsigned operands for bit manipulation.

The bitwise forms &=, |=, ^=, <<=, >>= exist too. Assignment is right-associative and yields the assigned value, so it can be chained:

int a, b, c;
a = b = c = 0;       // c = 0, then b = c, then a = b

int x = 10;
x *= 2 + 3;          // x = x * (2 + 3) = 50, NOT (x * 2) + 3

2.12 Increment and Decrement

++ adds 1 and -- subtracts 1. Each has a prefix and a postfix form that differ in the value the expression produces:

  • Pre-increment ++x: increment first, the expression yields the new value.
  • Post-increment x++: the expression yields the old value, then x is incremented.
int x = 5;
int a = ++x;    // x becomes 6 first, a = 6
int b = x++;    // b gets the old value 6, then x becomes 7
std::cout << a << ' ' << b << ' ' << x;   // 6 6 7

int y = 5;
std::cout << y-- << ' ';   // prints 5, y is now 4
std::cout << --y;          // y becomes 3, prints 3
Tip — default to prefix When you only need the side effect (as in for (...; ...; ++i)), prefer ++i. For built-in types the cost is identical, but for iterators and class types post-increment must create and return a temporary copy. Never modify the same variable twice in one expression (i = i++ + ++i is undefined behaviour).

Precedence decides which operator binds tighter; associativity breaks ties between operators of the same level. The table lists operators from highest to lowest precedence.

int r1 = 2 + 3 * 4;          // 14: * binds tighter than +
int r2 = (2 + 3) * 4;        // 20: parentheses override precedence
int r3 = 10 - 4 - 3;         // 3:  left-to-right ((10 - 4) - 3)
int r4 = 1 + 2 << 3;          // 24: + is higher than <<, so (1 + 2) << 3

int n = 6;
bool bad  = n & 1 == 0;      // parsed as n & (1 == 0) -> n & 0 -> 0   (WRONG)
bool good = (n & 1) == 0;    // true: n is even
When in doubt, add parentheses The bitwise operators rank below comparison operators, which is a classic source of bugs. Parentheses cost nothing at runtime and make your intent obvious to readers.

2.14 Key Takeaways

  • Pick the type that fits the data: int for counts, double for measurements, bool for flags, char for characters.
  • sizeof reports sizes in bytes at compile time; sizes vary between platforms.
  • Always initialize variables; prefer brace initialization to catch narrowing.
  • Unsigned overflow wraps; signed overflow is undefined behaviour.
  • Integer division truncates — convert an operand with static_cast<double> for a real quotient.
  • Prefer constexpr/const over #define; prefer static_cast over C-style casts.
  • &, |, ^, ~, <<, >> operate on bits; &&, ||, ! operate on truth values and short-circuit.
  • ++x yields the new value, x++ yields the old value.
  • Parenthesize when precedence is not obvious.
