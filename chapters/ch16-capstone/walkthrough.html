Chapter 16 — Walkthrough

A ten-step guide to building the Bank Account Management System, with the code for each step.

🎯 Brief 🗺 Walkthrough ✅ Solution

This guide builds the Bank Account Management System in ten small steps. Each step shows the code you should have written by the end of it. Try each step yourself first, then compare. Snippets are taken from the final program, so they fit together into the complete solution.

Order in the final file Because C++ requires declaration before use, the final file orders things as: includes → utilities (money, split, printAll) → exceptions (Step 7) → transaction (Step 2) → accounts (Steps 3–4) → customer (Step 5) → bank (Steps 6, 8) → UI (Step 9).

Step 1 — Set Up the Project Structure

Start by deciding where code will live. The reference solution is a single file (bank.cpp) so that it is easy to compile and share, but production projects split declarations into headers and definitions into source files. Either approach is fine for the capstone — choose one and stay consistent.

Recommended multi-file layout:

bank/
├── include/
│   ├── Exceptions.h      // BankException hierarchy
│   ├── Transaction.h     // TransactionType + Transaction
│   ├── Account.h         // Account, SavingsAccount, CheckingAccount
│   ├── Customer.h
│   └── Bank.h
├── src/
│   ├── Account.cpp
│   ├── Customer.cpp
│   ├── Bank.cpp
│   └── main.cpp          // menu-driven UI
└── Makefile

Step 2 — Design the Transaction Struct

A Transaction is a simple data record, so a struct is the natural choice. Use a scoped enum class for the type so values cannot be confused with plain integers, and add conversion helpers for printing and file I/O. 

enum class TransactionType { DEPOSIT, WITHDRAWAL, TRANSFER };

string toString(TransactionType t) {
    switch (t) {
        case TransactionType::DEPOSIT:    return "DEPOSIT";
        case TransactionType::WITHDRAWAL: return "WITHDRAWAL";
        case TransactionType::TRANSFER:   return "TRANSFER";
    }
    return "UNKNOWN";
}

struct Transaction {
    int id;                 // sequence number inside one account
    TransactionType type;
    double amount;          // signed: + money in, - money out
    double balanceAfter;
    string note;
};

Why signed amounts? Storing deposits as positive and withdrawals as negative lets a statement show direction without extra fields, and the sum of all amounts always equals the balance change.

Step 3 — Design the Account Base Class

Account holds the state common to every account and implements deposit() / withdraw() once. Behaviour that differs between account types is expressed as virtual functions. The key design trick: withdraw() asks the virtual availableFunds() how much may be taken, so the overdraft rule lives in the derived class and the base class never needs to know the concrete type.

Exceptions are thrown from here, so jump ahead to Step 7 if you want to define them first (they must appear above Account in the file). To keep this step compilable on its own, the version below already uses them. 

class Account {
public:
    Account(string id, int ownerId, double balance = 0.0)
        : id_(std::move(id)), ownerId_(ownerId), balance_(balance) {}
    virtual ~Account() = default;          // virtual: deleted via base pointer

    // Behaviour that differs per account type:
    virtual string typeName() const = 0;
    virtual char   typeCode() const = 0;   // 'S' or 'C' (used in the data file)
    virtual double extraValue() const = 0; // interest rate % or overdraft limit
    virtual string extraInfo() const = 0;  // human-readable version
    virtual double availableFunds() const { return balance_; }

    void deposit(double amount, TransactionType type = TransactionType::DEPOSIT,
                 const string& note = "Deposit") {
        requirePositive(amount);
        balance_ += amount;
        record(type, amount, note);
    }

    void withdraw(double amount, TransactionType type = TransactionType::WITHDRAWAL,
                  const string& note = "Withdrawal") {
        requirePositive(amount);
        if (amount > availableFunds())     // virtual call: overdraft-aware
            throw InsufficientFundsException(amount, availableFunds());
        balance_ -= amount;
        record(type, -amount, note);
    }

    // Used only when loading from file (does not touch the balance).
    void restoreTransaction(const Transaction& t) { history_.push_back(t); }

    const string& id() const { return id_; }
    int ownerId() const { return ownerId_; }
    double balance() const { return balance_; }
    const vector<Transaction>& history() const { return history_; }

private:
    static void requirePositive(double a) {
        if (!(a > 0.0)) throw InvalidAmountException(a);
    }
    void record(TransactionType type, double signedAmount, const string& note) {
        history_.push_back({static_cast<int>(history_.size()) + 1, type,
                            signedAmount, balance_, note});
    }

    string id_;
    int ownerId_;
    double balance_;
    vector<Transaction> history_;          // STL: transactions in a vector
};
Common mistake — forgetting the virtual destructor Deleting a SavingsAccount through an Account* without a virtual destructor is undefined behaviour. With shared_ptr created by make_shared<Derived> it would happen to work, but make the destructor virtual anyway.

Step 4 — Derive SavingsAccount and CheckingAccount

Each derived class adds one extra field and overrides the pure virtual functions. Only CheckingAccount overrides availableFunds(), which is exactly what implements overdraft protection. 

class SavingsAccount : public Account {
public:
    SavingsAccount(string id, int ownerId, double balance, double ratePercent)
        : Account(std::move(id), ownerId, balance), ratePercent_(ratePercent) {}

    string typeName() const override { return "Savings"; }
    char   typeCode() const override { return 'S'; }
    double extraValue() const override { return ratePercent_; }
    string extraInfo() const override {
        return "Interest rate " + money(ratePercent_) + "% (projected monthly interest " +
               money(balance() * ratePercent_ / 100.0 / 12.0) + ")";
    }

private:
    double ratePercent_;
};

class CheckingAccount : public Account {
public:
    CheckingAccount(string id, int ownerId, double balance, double overdraftLimit)
        : Account(std::move(id), ownerId, balance), overdraftLimit_(overdraftLimit) {}

    string typeName() const override { return "Checking"; }
    char   typeCode() const override { return 'C'; }
    double extraValue() const override { return overdraftLimit_; }
    string extraInfo() const override {
        return "Overdraft limit " + money(overdraftLimit_);
    }
    // Overdraft protection: you may spend up to balance + limit, no more.
    double availableFunds() const override { return balance() + overdraftLimit_; }

private:
    double overdraftLimit_;
};

// The tiny helper used above (put it near the top of the file):
string money(double v) {
    ostringstream os;
    os << fixed << setprecision(2) << v;
    return os.str();
}

Quick test — polymorphism in action:

shared_ptr<Account> a = make_shared<CheckingAccount>("T1", 1, 100.0, 50.0);
a->withdraw(120.0);                 // OK: 100 + 50 available -> balance -20
// a->withdraw(40.0);               // would throw: only 30 left
cout << a->balance() << '\n';       // -20

Step 5 — Implement the Customer Class

A Customer holds a std::map from account ID to account. The accounts are shared_ptrs because both the customer and the bank's master index refer to the same object. The map also gives alphabetical iteration by ID for free, and structured bindings make the loop readable. 

class Customer {
public:
    Customer(int id, string name) : id_(id), name_(std::move(name)) {}

    void addAccount(shared_ptr<Account> acc) {
        string key = acc->id();
        accounts_[key] = std::move(acc);
    }
    double totalBalance() const {
        double total = 0.0;
        for (const auto& [id, acc] : accounts_) total += acc->balance();
        return total;
    }

    int id() const { return id_; }
    const string& name() const { return name_; }
    const map<string, shared_ptr<Account>>& accounts() const { return accounts_; }

private:
    int id_;
    string name_;
    map<string, shared_ptr<Account>> accounts_;   // account id -> account
};

Step 6 — Implement the Bank Class

Bank is the facade the UI talks to. It owns the customers, keeps the master account index, hands out IDs, and implements the high-level operations. Notice how transfer() looks up both accounts before moving any money, so a bad ID can never leave half a transfer behind.

Core of the class (persistence and reports are added in later steps):

class Bank {
public:
    // Open an account ('S' savings / 'C' checking) for a customer name.
    // Existing customers are reused; new names create a new Customer.
    shared_ptr<Account> openAccount(const string& owner, char type, double param,
                                    double openingDeposit) {
        if (owner.empty() || owner.find('|') != string::npos)
            throw BankException("Customer name must be non-empty and must not contain '|'");
        if (type != 'S' && type != 'C')
            throw BankException("Unknown account type (use S or C)");
        if (param < 0.0) throw BankException("Rate / overdraft limit cannot be negative");
        if (openingDeposit < 0.0) throw InvalidAmountException(openingDeposit);

        // optional<int>: has a value only if the customer already exists
        int ownerId;
        if (auto existing = findCustomer(owner)) ownerId = *existing;
        else                                     ownerId = addCustomer(owner);

        string id = "ACC" + to_string(nextAccountNo_++);
        shared_ptr<Account> acc;
        if (type == 'S') acc = make_shared<SavingsAccount>(id, ownerId, 0.0, param);
        else             acc = make_shared<CheckingAccount>(id, ownerId, 0.0, param);

        if (openingDeposit > 0.0)
            acc->deposit(openingDeposit, TransactionType::DEPOSIT, "Opening deposit");

        accounts_[id] = acc;
        customers_.at(ownerId).addAccount(acc);
        return acc;
    }

    shared_ptr<Account> getAccount(const string& id) const {
        auto it = accounts_.find(id);
        if (it == accounts_.end()) throw AccountNotFoundException(id);
        return it->second;
    }

    void transfer(const string& fromId, const string& toId, double amount) {
        if (fromId == toId) throw BankException("Cannot transfer to the same account");
        auto from = getAccount(fromId);    // both lookups happen before any
        auto to   = getAccount(toId);      // money moves, so failures are clean
        from->withdraw(amount, TransactionType::TRANSFER, "Transfer to " + toId);
        to->deposit(amount, TransactionType::TRANSFER, "Transfer from " + fromId);
    }

private:
    optional<int> findCustomer(const string& name) const {
        auto it = ranges::find_if(customers_, [&](const auto& kv) {
            return kv.second.name() == name;
        });
        if (it == customers_.end()) return nullopt;
        return it->first;
    }

    int addCustomer(const string& name) {
        int id = nextCustomerId_++;
        customers_.emplace(id, Customer(id, name));
        return id;
    }

    map<int, Customer> customers_;                    // customer id -> customer
    map<string, shared_ptr<Account>> accounts_;       // account id  -> account
    int nextCustomerId_ = 1;
    int nextAccountNo_ = 1001;
};
Why shared_ptr here? The same Account object is referenced from Bank::accounts_ and from its owner's Customer::accounts_. Shared ownership expresses that precisely and frees the object automatically when the last reference disappears. (A unique_ptr design is also valid: let Bank own every account and give Customer only account IDs.)

Step 7 — Add Custom Exception Classes

Derive a base BankException from std::runtime_error, then add one subclass per kind of failure. Callers can catch the specific type they can handle (e.g. insufficient funds) or the base class to handle everything. Place these definitions before Account because Account::withdraw throws them. 

class BankException : public runtime_error {
public:
    explicit BankException(const string& msg) : runtime_error(msg) {}
};

class InsufficientFundsException : public BankException {
public:
    InsufficientFundsException(double requested, double available)
        : BankException("Insufficient funds: requested " + money(requested) +
                        ", available " + money(available)) {}
};

class InvalidAmountException : public BankException {
public:
    explicit InvalidAmountException(double amount)
        : BankException("Invalid amount: " + money(amount) + " (must be positive)") {}
};

class AccountNotFoundException : public BankException {
public:
    explicit AccountNotFoundException(const string& id)
        : BankException("Account not found: " + id) {}
};

class FileException : public BankException {
public:
    explicit FileException(const string& msg) : BankException("File error: " + msg) {}
};

// Usage: catch the most specific type first, the base class last.
try {
    bank.transfer("ACC1001", "ACC1002", 5000.0);
} catch (const InsufficientFundsException& e) {
    cout << "Declined: " << e.what() << '\n';
} catch (const BankException& e) {
    cout << "Error: " << e.what() << '\n';
}
Tip — always catch by const& Catching by value would slice the exception object and lose the derived type's message and behaviour.

Step 8 — Add File Persistence (Save / Load)

Use a simple line-based, pipe-delimited format. Each line starts with a record tag, which makes the parser a single if / else if chain and keeps the file human-readable: 

BANK|2|1003
CUSTOMER|1|Alice
ACCOUNT|S|ACC1001|1|400.00|2.50
TXN|ACC1001|1|DEPOSIT|500.00|500.00|Opening deposit
TXN|ACC1001|2|TRANSFER|-100.00|400.00|Transfer to ACC1002

Add these members to Bank (plus a split() helper and transactionTypeFromString()):

vector<string> split(const string& line, char delim) {
    vector<string> parts;
    string token;
    istringstream in(line);
    while (getline(in, token, delim)) parts.push_back(token);
    return parts;
}

TransactionType transactionTypeFromString(const string& s) {
    if (s == "DEPOSIT")    return TransactionType::DEPOSIT;
    if (s == "WITHDRAWAL") return TransactionType::WITHDRAWAL;
    if (s == "TRANSFER")   return TransactionType::TRANSFER;
    throw FileException("unknown transaction type '" + s + "'");
}

// ---- inside class Bank (public) ----
void save(const string& path) const {
    ofstream out(path);
    if (!out) throw FileException("cannot open '" + path + "' for writing");
    out << fixed << setprecision(2);
    out << "BANK|" << nextCustomerId_ << '|' << nextAccountNo_ << '\n';
    for (const auto& [id, c] : customers_)
        out << "CUSTOMER|" << id << '|' << c.name() << '\n';
    for (const auto& [id, a] : accounts_) {
        out << "ACCOUNT|" << a->typeCode() << '|' << id << '|' << a->ownerId() << '|'
            << a->balance() << '|' << a->extraValue() << '\n';
        for (const auto& t : a->history())
            out << "TXN|" << id << '|' << t.id << '|' << toString(t.type) << '|'
                << t.amount << '|' << t.balanceAfter << '|' << t.note << '\n';
    }
    if (!out) throw FileException("write to '" + path + "' failed");
}

void load(const string& path) {
    ifstream in(path);
    if (!in) throw FileException("cannot open '" + path + "' for reading");

    Bank loaded;                       // build into a temp: all-or-nothing load
    string line;
    int lineNo = 0;
    while (getline(in, line)) {
        ++lineNo;
        if (line.empty()) continue;
        try {
            loaded.parseLine(split(line, '|'));
        } catch (const exception& e) { // out_of_range, invalid_argument, BankException...
            throw FileException("line " + to_string(lineNo) + ": " + e.what());
        }
    }
    *this = std::move(loaded);         // commit
}

// ---- inside class Bank (private) ----
void parseLine(const vector<string>& f) {
    const string& tag = f.at(0);
    if (tag == "BANK") {
        nextCustomerId_ = stoi(f.at(1));
        nextAccountNo_  = stoi(f.at(2));
    } else if (tag == "CUSTOMER") {
        int id = stoi(f.at(1));
        customers_.emplace(id, Customer(id, f.at(2)));
    } else if (tag == "ACCOUNT") {
        int owner = stoi(f.at(3));
        double bal = stod(f.at(4)), extra = stod(f.at(5));
        shared_ptr<Account> acc;
        if (f.at(1) == "S")      acc = make_shared<SavingsAccount>(f.at(2), owner, bal, extra);
        else if (f.at(1) == "C") acc = make_shared<CheckingAccount>(f.at(2), owner, bal, extra);
        else throw FileException("unknown account type '" + f.at(1) + "'");
        accounts_[f.at(2)] = acc;
        customers_.at(owner).addAccount(acc);
    } else if (tag == "TXN") {
        Transaction t{stoi(f.at(2)), transactionTypeFromString(f.at(3)),
                      stod(f.at(4)), stod(f.at(5)), f.at(6)};
        getAccount(f.at(1))->restoreTransaction(t);
    } else {
        throw FileException("unknown record '" + tag + "'");
    }
}
Design note — all-or-nothing loading load() parses into a temporary Bank and only assigns it to *this after every line parsed successfully. A corrupt file therefore cannot leave the program with half-loaded data. Any error from the standard library (stoi, at) is converted to a FileException that names the line.

Step 9 — Add a Menu-Driven Console UI

The UI is a loop that prints a menu, reads a choice, and dispatches to Bank. Two small helpers read input safely: ask() reads a whole line (so spaces in names work), and askNumber() converts it with stod, turning bad input into a BankException. All bank errors are caught in one place inside the loop, so the program reports the problem and returns to the menu. 

struct InputClosed {};                     // thrown when stdin reaches EOF

string ask(const string& label) {
    cout << label;
    string s;
    if (!getline(cin, s)) throw InputClosed{};
    return s;
}

double askNumber(const string& label) {
    string s = ask(label);
    try {
        size_t used = 0;
        double v = stod(s, &used);
        if (used != s.size()) throw invalid_argument("trailing characters");
        return v;
    } catch (const exception&) {
        throw BankException("'" + s + "' is not a valid number");
    }
}

void printMenu() {
    cout << "\n--- Bank Menu ---\n"
         << " 1. Create Account\n 2. Deposit\n 3. Withdraw\n 4. Transfer\n"
         << " 5. View Statement\n 6. Save\n 7. Load\n 8. Exit\n";
}

int main() {
    const string dataFile = "bank_data.txt";
    Bank bank;

    if (ifstream(dataFile).good()) {       // auto-load on startup
        try { bank.load(dataFile); cout << "Loaded existing data.\n"; }
        catch (const BankException& e) { cout << e.what() << " (starting empty)\n"; }
    }

    try {
        bool running = true;
        while (running) {
            printMenu();
            string choice = ask("Choose an option: ");
            try {
                if (choice == "2") {
                    string id = ask("Account id: ");
                    double amt = askNumber("Amount to deposit: ");
                    auto acc = bank.getAccount(id);
                    acc->deposit(amt);
                    cout << "New balance: " << money(acc->balance()) << '\n';
                }
                // ... options 1, 3-7 follow the same pattern ...
                else if (choice == "8") running = false;
                else cout << "Please enter a number from 1 to 8.\n";
            } catch (const InsufficientFundsException& e) {
                cout << "Declined: " << e.what() << '\n';
            } catch (const BankException& e) {
                cout << "Error: " << e.what() << '\n';
            }
        }
    } catch (const InputClosed&) {
        cout << "\nInput closed.\n";
    }
    cout << "Goodbye!\n";
}

The complete set of menu branches is on the Solution page.

Pitfall — mixing cin >> and getline After cin >> x a newline remains in the buffer, and the next getline returns an empty string. Using getline for every prompt (as ask() does) avoids the problem entirely.

Step 10 — Add Modern C++ Polish

With the program working, refine it using the tools from Chapters 9, 11, and 15. The reference solution already uses most of these; here they are in isolation so you can see what each one buys you.

10a. A function template with a concept and a lambda formatter (Ch 9, 15)

One generic printer replaces separate "print accounts" and "print transactions" loops. The caller supplies a lambda that turns an element into text, and ranges::input_range restricts the template to real containers. 

template <ranges::input_range R, typename Formatter>
void printAll(const string& title, const R& items, Formatter fmt) {
    cout << "\n=== " << title << " ===\n";
    if (ranges::empty(items)) {
        cout << "  (none)\n";
        return;
    }
    for (const auto& item : items) cout << "  " << fmt(item) << '\n';
}

// Inside Bank — works with a map (pairs) ...
void listAccounts() const {
    printAll("Accounts", accounts_, [this](const auto& kv) {
        const Account& a = *kv.second;
        return a.id() + "  " + a.typeName() + "  owner=" +
               customers_.at(a.ownerId()).name() + "  balance=" + money(a.balance());
    });
}

// ... and with a vector<Transaction> (inside printStatement)
printAll("Transactions", acc->history(), [](const Transaction& t) {
    ostringstream os;
    os << '#' << setw(3) << left << t.id << setw(11) << toString(t.type)
       << right << setw(10) << money(t.amount) << "  balance " << setw(10)
       << money(t.balanceAfter) << "  " << t.note;
    return os.str();
});

10b. std::optional, auto, and ranges::find_if (Ch 15)

findCustomer() (Step 6) returns optional<int> — "an ID, or nothing" — instead of a magic value such as -1. The if (auto existing = …) form declares and tests it in one line. Remember that optional also offers value_or() and has_value().

10c. Sorting with a lambda (Ch 11, 15)

As a bonus, a "richest accounts first" report (add as a Bank method):

void printRichest() const {
    vector<shared_ptr<Account>> sorted;
    for (const auto& [id, acc] : accounts_) sorted.push_back(acc);   // structured bindings

    ranges::sort(sorted, [](const auto& a, const auto& b) {
        return a->balance() > b->balance();                          // descending
    });

    printAll("Accounts by balance", sorted, [](const auto& a) {
        return a->id() + "  " + money(a->balance());
    });
}

Final checklist

  • Compiles cleanly: g++ -std=c++20 -Wall -Wextra -o bank bank.cpp
  • No raw new / delete anywhere.
  • Every error path throws a BankException subclass; main() never terminates on bad input.
  • Save, restart, and view a statement — the history matches what you had before.
  • Large objects are passed by const&; getters are const.
