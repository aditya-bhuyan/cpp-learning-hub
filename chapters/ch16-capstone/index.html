Chapter 16 — Capstone Project

Bank Account Management System — a real-world project that brings together everything from Chapters 1–15.

🎯 Brief 🗺 Walkthrough ✅ Solution

16.1 Project Overview

Welcome to the capstone. Over fifteen chapters you have learned syntax, control flow, functions, pointers, classes, inheritance, templates, the STL, smart pointers, exceptions, file I/O, and modern C++. Now you will combine all of it in a single, realistic program: a console-based Bank Account Management System.

The system lets a bank clerk create customers and accounts, move money between accounts, review statements, and save everything to disk so the data survives between runs. It is small enough to finish in a weekend and rich enough to exercise every major C++ feature in this course.

Goals

  • Model a real domain with a clean class hierarchy and polymorphism.
  • Choose the right STL containers and own objects safely with smart pointers.
  • Report errors with a purpose-built exception hierarchy instead of return codes.
  • Persist and restore program state with file streams.
  • Write the finishing touches in idiomatic modern C++ (C++17/20).
Build command g++ -std=c++20 -Wall -o bank bank.cpp && ./bank
Your finished program should compile with no warnings under -Wall.

16.2 Functional Requirements

The program must provide the following behaviour. Each ID is referenced by the use cases and the grading rubric.

IDRequirement
FR-1Create a savings account (with an annual interest rate) or a checking account (with an overdraft limit) for a named customer, optionally with an opening deposit.
FR-2Each account gets a unique, automatically generated ID (e.g. ACC1001). A customer may own several accounts.
FR-3Deposit a positive amount into any account.
FR-4Withdraw a positive amount. Savings accounts may never go below zero; checking accounts may go negative but never beyond their overdraft limit.
FR-5Transfer money between two different accounts. A transfer is all-or-nothing: if the withdrawal fails, the deposit must not happen.
FR-6Record every deposit, withdrawal, and transfer as a Transaction (type, signed amount, balance after, note).
FR-7Display an account statement: account details, every transaction, and the current balance.
FR-8Save all customers, accounts, and transactions to a text file, and load them back (also automatically on startup if the file exists).
FR-9Present a menu-driven console UI: Create Account, Deposit, Withdraw, Transfer, View Statement, Save, Load, Exit.
FR-10Never crash on bad input: unknown accounts, negative amounts, insufficient funds, non-numeric input, and missing/corrupt files must produce a clear message and return to the menu.

16.3 Technical Requirements

The technical requirements map every chapter of the course onto a concrete part of the project.

AreaRequirementChapters

FundamentalsVariables, control flow, functions, strings, and references throughout; pass large objects by const&.1–6

16.5 Use Cases

UC-1 Create a New Account

ActorBank clerk
TriggerMenu option 1
Main flow1. Enter customer name. 2. Choose account type (S/C). 3. Enter interest rate (savings) or overdraft limit (checking). 4. Enter opening deposit (0 for none). 5. System creates the account, assigns an ID, and shows the account list.
ErrorsEmpty name, unknown type, negative rate/limit, or negative opening deposit → BankException subclass; no account is created.
RequirementsFR-1, FR-2, FR-6, FR-9

UC-2 Deposit Money

TriggerMenu option 2
Main flow1. Enter account ID. 2. Enter amount. 3. System increases the balance, records a DEPOSIT, and prints the new balance.
ErrorsUnknown account → AccountNotFoundException. Amount ≤ 0 or non-numeric → InvalidAmountException / BankException.
RequirementsFR-3, FR-6, FR-10

UC-3 Withdraw Money (with Overdraft Protection)

TriggerMenu option 3
Main flow1. Enter account ID. 2. Enter amount. 3. System compares the amount with availableFunds(). 4. If enough, balance decreases and a WITHDRAWAL is recorded.
Overdraft ruleSavings: available = balance. Checking: available = balance + overdraft limit. A request above the available amount is refused.
ErrorsRequest exceeds available funds → InsufficientFundsException (balance unchanged). Invalid amount or unknown account as in UC-2.
RequirementsFR-4, FR-6, FR-10

UC-4 Transfer Between Accounts

TriggerMenu option 4
Main flow1. Enter source ID, destination ID, and amount. 2. System looks up both accounts first. 3. Withdraws from source (TRANSFER). 4. Deposits into destination (TRANSFER).
ErrorsSame source and destination, unknown account, or insufficient funds. Because lookups and the withdrawal happen before the deposit, a failure leaves both balances untouched.
RequirementsFR-5, FR-6, FR-10

UC-5 View Account Statement

TriggerMenu option 5
Main flow1. System lists all accounts. 2. Enter an account ID. 3. System prints type, owner, interest rate/overdraft limit, every transaction, the current balance, and the available funds.
ErrorsUnknown account ID.
RequirementsFR-7, FR-10

UC-6 Save / Load Data

TriggerMenu options 6 (save) and 7 (load); automatic load at startup
Main flowSave: write customers, accounts, and transactions to bank_data.txt. Load: parse the file into a temporary Bank; only if everything parses, replace the current state.
ErrorsFile cannot be opened, unknown record type, or malformed number → FileException naming the offending line. The in-memory data is left intact.
RequirementsFR-8, FR-10

16.7 Getting Started

Do not try to write everything at once. Build in small, compilable increments and test after each one:

  1. Sketch on paper. Re-read the class tables above and draw the relationships yourself.
  2. Start with data. Write Transaction and its enum class. Print one from main().
  3. Build Account alone. Make deposit() and withdraw() work, then test with a throwaway main().
  4. Derive the two account types. Verify the overdraft rule through a base-class pointer — that is the payoff of polymorphism.
  5. Add Customer and Bank. Hard-code a few accounts and print a statement.
  6. Introduce exceptions and replace every return false/error print with a throw.
  7. Add persistence. Save first, inspect the file by eye, then write load.
  8. Wrap it in the menu. Only now read from cin.
  9. Polish with templates, lambdas, optional, and structured bindings. Compile with -Wall -Wextra.
Tip — Use the Walkthrough The Walkthrough follows exactly this order, with the code for each step. Try each step on your own first, then compare. The finished program is on the Solution page — resist peeking until you have a working version of your own.
Money and double This project uses double for simplicity. Real banking software stores integer cents (or a decimal type) because binary floating point cannot represent values such as 0.10 exactly. Stretch goal: change balance_ to long long cents.

16.8 Stretch Goals

  • Apply monthly interest to all savings accounts using std::for_each and a lambda.
  • Add a "top N richest customers" report with std::ranges::sort and a projection.
  • Replace the text file format with a more robust one (quoting, versioning, checksum).
  • Split the program into .h/.cpp files and build with a Makefile or CMake.
  • Write unit tests for Account::withdraw covering every boundary of the overdraft rule.
