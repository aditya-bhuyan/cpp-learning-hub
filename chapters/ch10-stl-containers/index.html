Chapter 10 — STL: Containers

Vectors, lists, maps, sets, and adaptors — the Standard Library's ready-made data structures.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

10.1 What is the STL?

The Standard Template Library (STL) is the part of the C++ standard library that provides ready-made, generic, highly optimised data structures and algorithms. Because it is built entirely on templates (Chapter 09), the same code works for int, std::string, or your own classes — with no runtime overhead from type erasure.

The STL has three cooperating components:

ComponentRoleExamples
ContainersObjects that store collections of elementsvector, map, set, queue
AlgorithmsGeneric functions that operate on ranges of elementssort, find, accumulate, reverse
IteratorsPointer-like objects that connect containers to algorithmsbegin(), end(), it++, *it

Iterators are the glue: an algorithm such as std::find never needs to know whether it is searching a vector or a list — it just walks a pair of iterators. This chapter focuses on containers; Chapter 11 covers algorithms and iterators in depth.

10.2 Container Categories

CategoryContainersKey idea
Sequencevector, list, deque, array, forward_listElements stored in the order you insert them; accessed by position
Associative (ordered)map, set, multimap, multisetKept sorted by key, typically a balanced red-black tree; O(log n) operations
Unordered (associative)unordered_map, unordered_set, unordered_multimap, unordered_multisetHash tables; O(1) average lookup, no ordering
Container adaptorsstack, queue, priority_queueRestricted interfaces built on top of another container

10.3 std::vector — Dynamic Array

std::vector is the default container in C++. It stores elements in one contiguous block of memory that grows automatically, giving you array-like speed with automatic memory management.

Header #include <vector> 
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> v;                 // empty vector of int
    v.reserve(100);                // pre-allocate space for 100 elements (size stays 0)

    v.push_back(10);               // append to the end
    v.push_back(20);
    v.push_back(30);

    cout << v.size()     << '\n';  // 3  - number of elements
    cout << v.capacity() << '\n';  // 100 - elements that fit before reallocation

    cout << v[1]      << '\n';     // 20 - unchecked access
    cout << v.at(1)   << '\n';     // 20 - bounds-checked (throws std::out_of_range)
    cout << v.front() << '\n';     // 10 - first element
    cout << v.back()  << '\n';     // 30 - last element

    v.insert(v.begin() + 1, 15);   // {10, 15, 20, 30} - insert before position 1
    v.erase(v.begin());            // {15, 20, 30}     - remove first element
    v.pop_back();                  // {15, 20}         - remove last element

    for (auto it = v.begin(); it != v.end(); ++it)   // iterator loop
        cout << *it << ' ';
    cout << '\n';

    cout << boolalpha << v.empty() << '\n';          // false
    v.clear();                                       // remove all elements
    cout << v.empty() << '\n';                       // true
    return 0;
}
MemberPurposeComplexity
push_back(x) / pop_back()Add / remove at the endAmortized O(1) / O(1)
v[i], at(i)Element access (at checks bounds)O(1)
front(), back()First / last elementO(1)
size(), capacity(), empty()Element count / allocated slots / emptiness testO(1)
reserve(n)Pre-allocate capacity to avoid reallocationsO(n) if it reallocates
insert(pos, x), erase(pos)Insert / remove at an iterator positionO(n) (elements shift)
clear()Remove all elementsO(n)
Why is push_back "amortized O(1)"? When size() == capacity(), the vector allocates a larger block (typically 1.5×–2× bigger) and moves every element over — an O(n) step. But this happens so rarely (the capacity grows geometrically) that, averaged over many push_back calls, each one costs constant time. If you know the final size, call reserve() first.
Iterator invalidation Any operation that reallocates (e.g. push_back on a full vector) invalidates all iterators, pointers, and references into the vector. insert/erase invalidate those at or after the change point.

10.4 std::list — Doubly-Linked List

std::list stores each element in its own node with pointers to the previous and next nodes. There is no random access (no operator[]); to reach the 50th element you must walk 50 nodes. In return, inserting or erasing anywhere is O(1) once you hold an iterator, and iterators stay valid when other elements are added or removed.

Header #include <list> 
#include <iostream>
#include <list>
using namespace std;

int main() {
    list<int> a = {1, 2, 3};
    a.push_back(4);        // {1, 2, 3, 4}
    a.push_front(0);       // {0, 1, 2, 3, 4}
    a.pop_front();         // {1, 2, 3, 4}
    a.pop_back();          // {1, 2, 3}

    // Insert in the middle in O(1) once we have the iterator
    auto it = a.begin();
    ++it;                  // points to 2
    a.insert(it, 99);      // {1, 99, 2, 3}

    // splice moves nodes from another list - no copying, O(1)
    list<int> b = {10, 20};
    a.splice(a.end(), b);  // a = {1, 99, 2, 3, 10, 20}, b is now empty

    for (int x : a) cout << x << ' ';
    cout << "\nb.size() = " << b.size() << '\n';   // 0
    return 0;
}

Prefer vector unless you genuinely need stable iterators or constant-time splicing: a vector's contiguous layout is far friendlier to the CPU cache, and it usually wins even for middle insertions on small to moderate sizes.

10.5 std::deque — Double-Ended Queue

std::deque (pronounced "deck") supports O(1) insertion and removal at both ends and O(1) random access via []. Internally it stores elements in a sequence of fixed-size chunks, so it is not contiguous like a vector. It is also the default underlying container for std::stack and std::queue.

Header #include <deque> 
#include <deque>
#include <iostream>
using namespace std;

int main() {
    deque<int> d = {2, 3, 4};
    d.push_front(1);      // {1, 2, 3, 4}  - O(1)
    d.push_back(5);       // {1, 2, 3, 4, 5} - O(1)
    d.pop_front();        // {2, 3, 4, 5}
    d.pop_back();         // {2, 3, 4}

    cout << d[0] << ' ' << d.at(2) << '\n';   // 2 4 - random access works
    cout << d.front() << ' ' << d.back() << '\n';
    return 0;
}

10.6 std::map — Ordered Key-Value Pairs

std::map<K, V> stores unique keys, each associated with a value, sorted by key. It is typically implemented as a self-balancing red-black tree, so lookup, insertion, and erasure are all O(log n). Iterating a map visits entries in ascending key order. Each element is a std::pair<const K, V>.

Header #include <map> 
#include <iostream>
#include <map>
#include <string>
using namespace std;

int main() {
    map<string, int> age;

    age["Alice"] = 30;                 // operator[]: inserts or overwrites
    age["Bob"]   = 25;
    age.insert({"Carol", 41});         // insert: does nothing if the key exists

    cout << age.at("Bob") << '\n';     // 25 - at() throws std::out_of_range if missing

    auto it = age.find("Carol");       // find returns end() if not found
    if (it != age.end())
        cout << it->first << " is " << it->second << '\n';

    cout << age.count("Dave") << '\n'; // 0 - count is 0 or 1 for map

    age.erase("Bob");                  // remove by key

    for (const auto& [name, years] : age)   // sorted by key: Alice, Carol
        cout << name << " = " << years << '\n';
    return 0;
}
operator[] inserts! Writing age["Zed"] when "Zed" is absent creates an entry with a default-constructed value (0 for int), even if you only meant to read it. Use find(), count(), or at() when you do not want to insert. (This is why operator[] cannot be used on a const map.)

10.7 std::unordered_map — Hash Map

std::unordered_map<K, V> has the same interface as map for the common operations but stores entries in a hash table. Lookup, insertion, and erasure are O(1) on average (O(n) in the worst case when many keys collide). Iteration order is unspecified. Keys need a std::hash specialisation and operator==.

Header #include <unordered_map> 
#include <iostream>
#include <string>
#include <unordered_map>
using namespace std;

int main() {
    unordered_map<string, double> price;
    price["apple"]  = 0.50;
    price["banana"] = 0.25;
    price["cherry"] = 3.00;

    if (price.find("banana") != price.end())
        cout << "banana costs " << price["banana"] << '\n';

    price.erase("apple");
    cout << "items: " << price.size() << '\n';   // 2
    // Do NOT rely on the order in which entries are visited
    return 0;
}

10.8 std::set — Ordered Unique Elements

std::set<T> stores unique elements in sorted order (again, usually a red-black tree). Insertion, lookup, and erasure are O(log n). Inserting a value that already exists has no effect — a handy way to remove duplicates. Elements are effectively const: you cannot modify them in place, only erase and re-insert.

Header #include <set> 
#include <iostream>
#include <set>
using namespace std;

int main() {
    set<int> s = {5, 1, 3, 3, 1};     // duplicates ignored -> {1, 3, 5}

    auto result = s.insert(3);        // pair<iterator, bool>
    cout << boolalpha << result.second << '\n';   // false - already present

    s.insert(4);                      // {1, 3, 4, 5}
    cout << s.count(4) << '\n';       // 1 - is 4 in the set?
    s.erase(1);                       // {3, 4, 5}

    for (int x : s) cout << x << ' '; // 3 4 5 (sorted)
    cout << '\n';
    return 0;
}

10.9 std::unordered_set — Hash Set

std::unordered_set<T> is the hash-table version of set: unique elements, O(1) average insertion/lookup/erasure, and no defined order. Choose it when you only need fast "is this value present?" checks.

Header #include <unordered_set> 
#include <iostream>
#include <string>
#include <unordered_set>
using namespace std;

int main() {
    unordered_set<string> seen;
    seen.insert("red");
    seen.insert("green");
    seen.insert("red");               // ignored - already present

    cout << seen.size() << '\n';      // 2
    cout << (seen.count("green") ? "found" : "missing") << '\n';
    seen.erase("green");
    return 0;
}

10.10 Container Adaptors

An adaptor wraps an existing container and exposes a deliberately restricted interface. Adaptors have no iterators — you can only touch the "ends" the abstraction allows.

std::stack — LIFO

A Last-In, First-Out structure built (by default) on std::deque. Operations: push, pop, top, empty, size. Header: #include <stack>. 

#include <iostream>
#include <stack>
using namespace std;

int main() {
    stack<int> st;
    st.push(1);
    st.push(2);
    st.push(3);

    cout << st.top()  << '\n';   // 3 - peek at the newest element
    st.pop();                    // removes 3 (pop returns void!)
    cout << st.top()  << '\n';   // 2
    cout << st.size() << '\n';   // 2
    cout << boolalpha << st.empty() << '\n';   // false
    return 0;
}

std::queue — FIFO

A First-In, First-Out structure, also built on std::deque by default. Operations: push (to the back), pop (from the front), front, back, empty, size. Header: #include <queue>. 

#include <iostream>
#include <queue>
using namespace std;

int main() {
    queue<int> q;
    q.push(1);
    q.push(2);
    q.push(3);

    cout << q.front() << ' ' << q.back() << '\n';   // 1 3
    q.pop();                                        // removes 1 (the oldest)
    cout << q.front() << '\n';                      // 2
    cout << q.size()  << '\n';                      // 2
    return 0;
}

std::priority_queue — Max-Heap

A priority_queue always keeps the largest element on top (a max-heap, built on vector by default). Operations: push (O(log n)), pop (O(log n)), top (O(1)). Header: #include <queue> (same header as queue). For a min-heap, supply std::greater. 

#include <functional>   // std::greater
#include <iostream>
#include <queue>
#include <vector>
using namespace std;

int main() {
    priority_queue<int> maxHeap;             // largest on top
    for (int x : {4, 9, 1, 7}) maxHeap.push(x);

    cout << maxHeap.top() << '\n';           // 9
    maxHeap.pop();
    cout << maxHeap.top() << '\n';           // 7

    priority_queue<int, vector<int>, greater<int>> minHeap;   // smallest on top
    for (int x : {4, 9, 1, 7}) minHeap.push(x);
    cout << minHeap.top() << '\n';           // 1
    return 0;
}

10.11 Choosing the Right Container

ContainerHeaderOrdered?LookupInsert / EraseUse it when…
vector<vector>By positionO(1) by index; O(n) by valueAmortized O(1) at end; O(n) middleDefault choice; fast iteration and indexing
list<list>By positionO(n)O(1) with iteratorFrequent middle insert/erase, need stable iterators, splicing
deque<deque>By positionO(1) by indexO(1) at both endsAdd/remove at both ends
map<map>Sorted by keyO(log n)O(log n)Key-value data that must stay sorted or needs range queries
unordered_map<unordered_map>NoO(1) avgO(1) avgFast key-value lookup; order irrelevant
set<set>SortedO(log n)O(log n)Unique values, sorted iteration
unordered_set<unordered_set>NoO(1) avgO(1) avgFast membership tests
stack<stack>LIFOtop onlyO(1)Undo, parsing, DFS, bracket matching
queue<queue>FIFOfront/back onlyO(1)Job queues, BFS, buffering
priority_queue<queue>Max on toptop onlyO(log n)Schedulers, Dijkstra, top-k problems
Rule of thumb Start with std::vector. Switch only when profiling or the problem's shape tells you otherwise: need key lookup → unordered_map (or map if sorted order matters); need uniqueness → set/unordered_set; need LIFO/FIFO/priority behaviour → the matching adaptor.

10.12 Key Takeaways

  • The STL = containers + algorithms + iterators, all built on templates.
  • vector is contiguous, indexable, and has amortized O(1) push_back; use reserve() when the size is known.
  • list has no random access but O(1) insert/erase at an iterator; deque is O(1) at both ends.
  • map/set are sorted (O(log n)); unordered_map/unordered_set are hashed (O(1) average).
  • map::operator[] inserts a default-constructed value for missing keys — use find/at to avoid that.
  • stack is LIFO, queue is FIFO, priority_queue is a max-heap by default; pop() returns void on all three.
