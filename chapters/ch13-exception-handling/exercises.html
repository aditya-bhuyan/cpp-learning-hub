Chapter 13 — Exercises

Apply what you've learned about exception handling. Attempt each problem before viewing the solutions.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz
Instructions Work through each exercise in a text editor or IDE. Compile with g++ -std=c++17 -Wall. Only open Solutions after you have made a genuine attempt.
Exercise 1 — Safe Division Function Easy

Write a function safeDiv(int a, int b) that:

  1. Returns the integer result of a / b when b != 0.
  2. Throws std::invalid_argument with the message "safeDiv: divisor cannot be zero" when b == 0.

In main(), call safeDiv with several pairs including a zero divisor. Catch the exception and print a clear error message. Execution should continue after the catch.

Expected output (sample):

10 / 2 = 5
15 / 3 = 5
Error: safeDiv: divisor cannot be zero
8 / 4 = 2
Exercise 2 — Parsing a Positive Integer Easy

Write a function int parsePositiveInt(const std::string& s) that:

  1. Parses s as an integer using std::stoi (which itself can throw std::invalid_argument or std::out_of_range).
  2. If the parsed integer is not strictly positive (<= 0), throws std::invalid_argument with message "Input must be a positive integer".
  3. Otherwise returns the parsed integer.

Test with the inputs: "42", "-7", "0", "abc", and "99999999999" (too large for int). Catch each exception and print what went wrong. Use std::stoi inside your function.

Hint: Wrap std::stoi in a try/catch inside parsePositiveInt, or let its exceptions propagate naturally — both are valid designs.

Expected output (sample):

42: parsed OK = 42
-7: invalid_argument: Input must be a positive integer
0: invalid_argument: Input must be a positive integer
abc: invalid_argument: stoi
99999999999: out_of_range: stoi
Exercise 3 — InsufficientFundsException with BankAccount Medium

Create a custom exception class InsufficientFundsException that:

  • Inherits from std::exception (or std::runtime_error).
  • Stores the requested amount and the current balance as double members.
  • Overrides what() to return a descriptive message including both values.
  • Provides requestedAmount() and currentBalance() accessors.

Create a BankAccount class with a double balance and a void withdraw(double amount) method that throws InsufficientFundsException when amount > balance.

In main(), create an account with balance 500.00. Try withdrawals of 200.00, 150.00, and 200.00. Catch the exception on the third withdrawal and print both the what() message and the shortfall (requested - balance).

Expected output (sample):

Withdrew 200.00. Balance: 300.00
Withdrew 150.00. Balance: 150.00
Exception: Insufficient funds — requested 200.00, available 150.00
Shortfall: 50.00
Exercise 4 — Exception Propagation Through a Call Chain Medium

Write three functions:

  • void funcC() — throws std::runtime_error("Error in C").
  • void funcB() — calls funcC() but does not catch; the exception propagates through.
  • void funcA() — calls funcB() inside a try block and catches std::runtime_error.

In funcA's catch block, print the caught message and then add context by rethrowing a new std::runtime_error that wraps the original message: "funcA caught and translated: [original message]".

In main(), call funcA() inside another try/catch and print the final message. Also add a catch(...) safety net that prints "Unknown exception reached main".

Add a std::cout trace line at the start of each function to make propagation visible.

Expected output (sample):

Entering funcA
Entering funcB
Entering funcC
funcA caught: Error in C
main caught translated: funcA caught and translated: Error in C
Exercise 5 — Strong Exception-Safe Transaction Manager Hard

Implement a TransactionManager class that applies a sequence of integer operations to a data store with strong exception safety: either all operations succeed, or the data store is left in its original state.

The class must have:

  • std::vector<int> data — publicly accessible for testing.
  • void applyAll(const std::vector<std::function<void(std::vector<int>&)>>& ops) — applies each operation in sequence. If any operation throws, the data vector is restored to the state it had before applyAll was called.

Write three lambda operations: one that appends 10, one that appends 20, and one that throws std::runtime_error("Op 3 failed"). Call applyAll with all three. Verify that data is unchanged after the exception. Then call again with only the two successful operations and verify they applied.

Hint: Make a copy of data at the start of applyAll. On exception, restore from the copy (copy-and-swap or assign-back pattern).

Expected output (sample):

Before transaction: []
Transaction 1 failed: Op 3 failed
After failed transaction: []   <-- unchanged!
Transaction 2 succeeded.
After successful transaction: [10, 20]
