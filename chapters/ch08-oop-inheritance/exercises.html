Chapter 08 — Exercises

Apply what you've learned. Attempt each problem before viewing the solutions.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz
Instructions Work through each exercise in a text editor or IDE. Compile with g++ -std=c++17 -Wall and run your program. Only open Solutions after you have made a genuine attempt.
Exercise 1 — Vehicle, Car and Truck Easy

Create a base class Vehicle with the data members make (string), model (string) and year (int), a constructor that sets them, and a member function display() that prints them. Then derive two classes:

  • Car — adds numDoors (int)
  • Truck — adds payloadTons (double)

Each derived class must call the Vehicle constructor from its own constructor, and its display() should print the common data plus its own.

Hints:

  • Use the initializer list: Car(...) : Vehicle(make, model, year), numDoors(doors) { }
  • Make display() virtual in the base class and mark the overrides with override.
  • A derived display() may call Vehicle::display() to avoid repeating code.

Expected output:

Toyota Corolla (2021)
  Doors: 4
Volvo FH16 (2019)
  Payload: 18.5 tons
Exercise 2 — Abstract PaymentMethod Easy

Create an abstract class PaymentMethod with a pure virtual function bool processPayment(double amount). Implement two concrete classes:

  • CreditCard — has a creditLimit and a running balance (amount already charged). A payment succeeds only if it keeps the balance within the limit.
  • Cash — has an amount of cashOnHand. A payment succeeds only if there is enough cash, and it reduces the cash.

In main, process payments through a PaymentMethod& parameter to prove they work polymorphically.

Hints:

  • Don't forget the virtual destructor in the abstract base.
  • Verify that PaymentMethod p; does not compile.

Expected output:

Credit card: charged $250.00 (balance $250.00 / limit $500.00)
Credit card: DECLINED $300.00 (would exceed limit)
Cash: paid $40.00 (remaining $60.00)
Cash: DECLINED $75.00 (insufficient cash)
Exercise 3 — Person → Employee → Manager Medium

Build a three-level hierarchy:

  • Person — name
  • Employee : public Person — adds salary and role
  • Manager : public Employee — adds a team size (numReports)

Each class has a virtual std::string toString() const that overrides the one above it and reuses the parent's output (call Parent::toString()). Write a function void show(const Person& p) that prints p.toString(), and call it with objects of all three types.

Hints:

  • Constructors chain: Manager(...) : Employee(name, salary, role), numReports(n) { }
  • Use std::ostringstream or string concatenation with std::to_string to build the text.
  • Because show takes a reference to Person, the call is dispatched dynamically. What would happen if it took Person by value?

Expected output:

Name: Alice
Name: Bob | Role: Developer | Salary: 65000.00
Name: Carol | Role: Engineering Manager | Salary: 95000.00 | Reports: 6
Exercise 4 — Shapes in a Vector Medium

Create an abstract class Shape with pure virtual double area() const and std::string name() const. Derive Triangle (base, height), Rectangle (width, height) and Circle (radius). Store one of each (plus an extra circle) in a std::vector<Shape*>, print the area of every shape with a single loop, then free the memory correctly.

Hints:

  • Triangle area is 0.5 * base * height; circle area is π r².
  • A virtual destructor in Shape is mandatory when you delete through a Shape*.
  • Print with two decimal places using fixed and setprecision(2).

Expected output:

Triangle  area = 12.00
Rectangle area = 28.00
Circle    area = 78.54
Circle    area = 3.14
Exercise 5 — A Simple Logger Plugin Interface Hard

Design a tiny "plugin" system. Define an abstract interface Logger with a pure virtual function void log(const std::string& message) and a virtual destructor. Implement:

  • ConsoleLogger — prints [CONSOLE] message to cout.
  • FileLogger — takes a file name in its constructor and simulates writing to it by printing [FILE app.log] message to cout. Its constructor prints "Opening ..." and its destructor prints "Closing ...".

Then write a class Application that does not know which logger it uses: it receives a Logger& in its constructor and calls log() from its run() method. In main, create a vector<unique_ptr<Logger>> holding both loggers, and run one Application per logger.

Hints:

  • This is the dependency inversion idea: high-level code depends on the abstraction, not on concrete classes.
  • Create objects with make_unique<ConsoleLogger>() and push them into the vector (#include <memory>).
  • Check the "Opening"/"Closing" lines to confirm the virtual destructor is working when the vector is destroyed.

Expected output:

Opening app.log
[CONSOLE] Application started
[CONSOLE] Application finished
[FILE app.log] Application started
[FILE app.log] Application finished
Closing app.log
