Chapter 04 — Coding Examples

Four fully commented, compilable programs demonstrating factorial, overloading, pass-by-reference, and memoized Fibonacci.

📖 Learning 💻 Examples ✏️ Exercises ✅ Solutions 🧠 Quiz

Example 1 — Factorial: Iterative vs Recursive

This program computes n! two ways side by side. The iterative version uses a loop; the recursive version calls itself. Comparing them shows that recursion can express a mathematical definition directly, while iteration is often more memory-efficient (no function-call overhead). 

// factorial.cpp
// Compile: g++ -std=c++17 -Wall -o factorial factorial.cpp
// Run:     ./factorial

#include <iostream>
using namespace std;

// ── Iterative version ────────────────────────────────────────────
// Uses a simple loop to accumulate the product 1 × 2 × … × n
// Time complexity: O(n)  |  Space complexity: O(1)
long long factIterative(int n) {
    if (n < 0) return -1;     // undefined for negative input
    long long result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

// ── Recursive version ────────────────────────────────────────────
// Expresses the mathematical definition directly: n! = n × (n-1)!
// Base case: 0! = 1  (and 1! = 1)
// Time complexity: O(n)  |  Space complexity: O(n) — one stack frame per call
long long factRecursive(int n) {
    if (n <= 1) return 1;           // base case
    return n * factRecursive(n - 1); // recursive case
}

int main() {
    cout << "n\tIterative\tRecursive\n";
    cout << "--\t---------\t---------\n";
    for (int n = 0; n <= 12; ++n) {
        cout << n << "\t"
             << factIterative(n) << "\t\t"
             << factRecursive(n) << "\n";
    }
    return 0;
}

Expected output:

n       Iterative       Recursive
--      ---------       ---------
0       1               1
1       1               1
2       2               2
3       6               6
4       24              24
5       120             120
6       720             720
7       5040            5040
8       40320           40320
9       362880          362880
10      3628800         3628800
11      39916800        39916800
12      479001600       479001600
Why does recursion use more memory? Each recursive call to factRecursive pushes a new stack frame containing the local variable n and the return address. For n = 12 that is 12 frames. For very large n (thousands or more) the iterative version is safer.

Example 2 — Function Overloading: area() for Three Shapes

Three overloads of area() compute the area of a circle, a rectangle, and a triangle. The compiler selects the correct version based on the number and types of arguments. 

// area_overload.cpp
// Compile: g++ -std=c++17 -Wall -o area_overload area_overload.cpp

#include <iostream>
#include <iomanip>   // setprecision, fixed
using namespace std;

const double PI = 3.14159265358979;

// ── Overload 1: circle ────────────────────────────────────────────
// Parameter: radius (double)
// Formula:   A = π × r²
double area(double radius) {
    return PI * radius * radius;
}

// ── Overload 2: rectangle ─────────────────────────────────────────
// Parameters: width (double), height (double)
// Formula:    A = w × h
double area(double width, double height) {
    return width * height;
}

// ── Overload 3: triangle ──────────────────────────────────────────
// Parameters: base (double), height (double), isTriangle (bool sentinel)
// The bool parameter distinguishes this overload from the rectangle overload.
// Formula:    A = ½ × b × h
double area(double base, double height, bool /*isTriangle*/) {
    return 0.5 * base * height;
}

int main() {
    cout << fixed << setprecision(4);

    // Calls overload 1 (single double)
    cout << "Circle    (r=5):        area = " << area(5.0)            << "\n";

    // Calls overload 2 (two doubles)
    cout << "Rectangle (4 x 6):      area = " << area(4.0, 6.0)       << "\n";

    // Calls overload 3 (two doubles + bool)
    cout << "Triangle  (b=3, h=8):   area = " << area(3.0, 8.0, true) << "\n";

    return 0;
}

Expected output:

Circle    (r=5):        area = 78.5398
Rectangle (4 x 6):      area = 24.0000
Triangle  (b=3, h=8):   area = 12.0000
Overload resolution: The compiler matches the call to an overload by looking at the number and types of the arguments. If no exact match exists, it tries implicit conversions. An ambiguous match (two equally good candidates) is a compile error.

Example 3 — Pass by Value vs Pass by Reference: swap()

This program implements two versions of swap() — one using pass-by-value (which fails to swap the originals) and one using pass-by-reference (which correctly exchanges them). The contrast makes the difference concrete and unforgettable. 

// swap_demo.cpp
// Compile: g++ -std=c++17 -Wall -o swap_demo swap_demo.cpp

#include <iostream>
using namespace std;

// ── BAD: pass by value ────────────────────────────────────────────
// The function receives COPIES of a and b.
// Swapping the copies has no effect on the caller's variables.
void swapByValue(int a, int b) {
    int temp = a;
    a = b;
    b = temp;
    // a and b are destroyed here — the caller never sees the change
    cout << "  [inside swapByValue]  a=" << a << "  b=" << b << "\n";
}

// ── GOOD: pass by reference ───────────────────────────────────────
// a and b are ALIASES for the caller's variables.
// Swapping them directly modifies the originals.
void swapByRef(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
    cout << "  [inside swapByRef]    a=" << a << "  b=" << b << "\n";
}

int main() {
    int x = 10, y = 20;

    // ── Attempt 1: pass by value (fails)
    cout << "Before swapByValue: x=" << x << "  y=" << y << "\n";
    swapByValue(x, y);
    cout << "After  swapByValue: x=" << x << "  y=" << y << "\n\n";

    // ── Attempt 2: pass by reference (succeeds)
    cout << "Before swapByRef:   x=" << x << "  y=" << y << "\n";
    swapByRef(x, y);
    cout << "After  swapByRef:   x=" << x << "  y=" << y << "\n";

    return 0;
}

Expected output:

Before swapByValue: x=10  y=20
  [inside swapByValue]  a=20  b=10
After  swapByValue: x=10  y=20

Before swapByRef:   x=10  y=20
  [inside swapByRef]    a=20  b=10
After  swapByRef:   x=20  y=10

Example 4 — Fibonacci with Memoization Using a Static Local Array

A naive recursive Fibonacci function recomputes the same values exponentially many times. This example uses a static local array as a memo table: the array is initialised once (on the first call) and persists across subsequent calls, turning an O(2n) algorithm into O(n). 

// fibonacci_memo.cpp
// Compile: g++ -std=c++17 -Wall -o fibonacci_memo fibonacci_memo.cpp

#include <iostream>
using namespace std;

// ── Naive recursive Fibonacci (for comparison) ────────────────────
// Time complexity: O(2^n) — catastrophically slow for large n
long long fibNaive(int n) {
    if (n <= 1) return n;
    return fibNaive(n - 1) + fibNaive(n - 2);
}

// ── Memoized recursive Fibonacci ─────────────────────────────────
// Uses a static local array: initialised once, survives between calls.
// 'static' means the array is allocated in static storage, not the stack,
// and its lifetime is the entire program run.
// Time complexity: O(n)  |  Space complexity: O(n)
long long fibMemo(int n) {
    const int MAX_N = 93;               // fib(93) is the largest that fits in long long
    static long long memo[MAX_N + 1];   // static: only initialised once
    static bool      ready = false;

    if (!ready) {                       // first call only: fill the table
        memo[0] = 0;
        memo[1] = 1;
        for (int i = 2; i <= MAX_N; ++i)
            memo[i] = memo[i - 1] + memo[i - 2];
        ready = true;
    }

    if (n < 0 || n > MAX_N) return -1; // out of range
    return memo[n];
}

int main() {
    cout << "n\tNaive\t\tMemoized\n";
    cout << "--\t-----\t\t--------\n";

    // Print first 20 values (naive is still tolerable at n=20)
    for (int n = 0; n <= 20; ++n) {
        cout << n << "\t"
             << fibNaive(n) << "\t\t"
             << fibMemo(n)  << "\n";
    }

    // Show the power of memoization for large n
    cout << "\nLarge values (memoized only):\n";
    cout << "fib(50) = " << fibMemo(50) << "\n";
    cout << "fib(70) = " << fibMemo(70) << "\n";
    cout << "fib(93) = " << fibMemo(93) << "\n";

    return 0;
}

Expected output (first 20 lines then large values):

n       Naive           Memoized
--      -----           --------
0       0               0
1       1               1
2       1               1
3       2               2
4       3               3
5       5               5
...
20      6765            6765

Large values (memoized only):
fib(50) = 12586269025
fib(70) = 190392490709135
fib(93) = 12200160415121876738
Static local variables are a lightweight memoization technique. They are initialised exactly once (at the first call to the function) and keep their value between calls, unlike ordinary local variables which are destroyed at each function exit.
